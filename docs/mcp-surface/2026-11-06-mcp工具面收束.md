# MCP 工具面收束 — 整改方案

日期：2026-11-06
状态：已落地。对外只注册 `vault_list`、`vault_describe`、`http_call`、`git`、`mail`、`vault_revoke`。凭据 profile 加密随条目保存，可在桌面和 Android 编辑；GitHub 与 ZoomKey 使用内置配方。
产品名：Sealbox（印盒）
仓库：`/project/sealbox`

## 1. 问题

MCP 按平台、按接口各注册一个工具。GitHub API、ZoomKey Jira、ZoomKey CRM、邮箱各自一套名字。密码和平台一多，就要改 Rust、发一版，`tools/list` 也会把模型撑满。

Git 已经收成 `github_git` + `action`，但 GitHub API 仍把细工具整表挂出；`github_issue` / `github_pr` / `github_release` 的 action 分发没有成为对外的唯一形态。凭据经纪人规格（`docs/superpowers/specs/2026-09-24-credential-broker-mcp-design.md`）写过通用 GET，尚未落地，且「任意 path」仍会让模型自己拼接口。

## 2. 结论

工具表稳定，不跟着密码涨。平台差异放进凭据上的 profile，人在界面里改。MCP 继续执行请求，不是只留一份配置。

没有「先藏起工具，按场景再发给模型」这一步。`tools/list` 里有什么，运行时就只有什么。模型不会中途拿到第二份工具表。

## 3. 对外工具

只注册这些：

| 工具 | 作用 |
|---|---|
| `vault_list` | 标题、类型、服务、origin、已登记操作名。不含秘密、备注、Token |
| `vault_describe` | 某一条凭据的操作说明书：方法、路径模板、参数、风险 |
| `http_call` | 唯一的远程 HTTP 入口。参数是凭据 ID、操作名、该操作声明的参数 |
| `git` | 本机 git。`action`：status、diff、log、branches、fetch、pull、commit、push、clone |
| `mail` | 邮箱。`action`：accounts、list、read、save |
| `vault_revoke` | 吊销当前调用方尚未用完的授权 |

GitHub、Gitee、Jira、CRM 不再出现在工具名里。旧名只在服务端做别名，调用时转成 `action` 或 `http_call` 的操作名，不出现在 `tools/list`。

## 4. 什么留在代码，什么改成配置

留在代码里：

- 列元数据、读配方，且不返回明文。
- `http_call`：按配方拼请求、注入认证、锁 origin、禁止模型改头、脱敏、截断、审计。写操作默认放行，仅破坏性写操作（如 git 强制推送）逐次桌面确认。
- `git` 和 `mail`：协议适配器。二者不是普通 REST，不能收成 HTTP 配方。
- 拒绝未知操作、路径越界、把明文写进工具结果。

改成凭据 profile 的：

- 固定 origin、认证方式（Bearer、Basic、自定义头、mTLS）。
- 允许的方法和路径前缀。
- 具名操作。例如 `search_issues` = `GET /rest/api/2/search`，查询参数白名单，以及该操作的风险。
- GitHub 现有路径与 DTO 裁剪，收成一份内置 GitHub profile，而不是继续注册 `github_repo_list` 这类工具。检查仍锁死 `api.github.com`（上传锁 `uploads.github.com`）。

没有 profile 的平台不暴露操作，避免退回开放代理。模型不能自己拼主机、改请求头或换认证方式。

ZoomKey 的 `zoomkey_jira_*` / `zoomkey_crm_*` 若是同一条 mTLS 通道上的不同路径，收成该凭据的配方。`nav` 可留成一条只读操作，返回建议的下一步，不再为此注册十个工具。

## 5. 模型怎么知道参数

Git 和邮件靠这一个工具的 schema，不靠工具个数：

- `action` 用枚举列死。
- 每个参数注明哪种 action 才用。
- `additionalProperties: false`。
- 未知 `action` 的错误带回合法列表。

`http_call` 的菜单每条凭据不同，所以先 `vault_list`，再 `vault_describe`，然后 `http_call(credential_id, op, params)`。describe 返回的是操作说明书，不是新的 MCP 工具。

## 6. 明确不做

- 不把秘密存进笔记、对话或插件配置。
- 不提供 `export_all`，不把 Token 回给模型。
- 不把「任意 URL / 方法 / 请求头」交给模型。
- 不为每个新接口增加一个工具名。
- 不在调用过程中动态往 `tools/list` 追加工具。

## 7. 落地顺序

1. `git`、`mail` 对外只留带 `action` 的各一个工具；旧名仅内部分发。
2. 凭据 profile 与 `vault_list` / `vault_describe`。
3. `http_call` 执行器，先挂内置 GitHub profile，行为与现有裁剪、确认、审计一致。
4. ZoomKey Jira / CRM 收成 profile；确认无回归后再从 `tools/list` 移除细工具名。

成功标准：平台和密码增加时，MCP 工具表不变；新增能力是界面里的一条配方，不是一次工具注册。
