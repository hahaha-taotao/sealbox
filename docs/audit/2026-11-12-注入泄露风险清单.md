# 注入与泄露类风险清单（2026-11-12）

范围：只收「注入执行」与「明文出库/外传」两类。每条均已逐行核对代码。

分类口径：
- **INJ** = 注入执行（能改变程序行为的输入 —— 路径、消息、钩子、命令）
- **EXF** = 泄露/外传（秘密或敏感数据流向不该看到它的一方）

---

## 一、注入执行（INJ）

### INJ-1 · `git` 工具允许改写 `.git/hooks/*` 与 CI 配置 → 宿主机任意命令执行
**严重度：高（需 MCP 已启用）**

- **证据**：`src-tauri/src/git_workspace.rs:736-751` `rel_path()` 只拒绝绝对路径与 `..`，其余一律放行；`prepare_commit`(`:378-422`) 用 `git add -- <files>` / `git add -A` 后 `git commit`。
- **攻击链**：模型调 `git` 写入 `.git/hooks/pre-commit`（或 `post-checkout`、`pre-push`）→ 内容为任意 shell → 下一次 `git` 写操作触发 hook → **在 Sealbox 宿主机上以当前用户身份执行任意命令**。等价路径：写 `.github/workflows/*.yml` 后 `push`，让远端 CI 在持有 secrets 的环境执行模型指定的构建脚本。
- **前提**：用户启用 MCP 并配置了 git 凭据（默认写操作放行，见 INJ-2）。
- **为何算产品级不足**：README 把 `git` 描述为「本机 git」，给人的印象是版本控制操作；实际它是一条宿主机代码执行通道，且没有任何「仅限用户登记过的仓库」约束。

### INJ-2 · 确认机制是空壳，所有写操作静默放行（放大 INJ-1、INJ-3）
**严重度：高**

- **证据**：`src-tauri/src/confirm.rs:127-137`，`ask_payload()` 在 `payload.dangerous == false` 时**直接 return true**，不弹窗。而：
  - `git_workspace.rs:267` `git_confirm_payload` → `dangerous: false`
  - `profile_http.rs:125-140` 所有 profile 写操作 → `dangerous: false`
  - `http_profiles.rs:359-377` → `dangerous: false`
  - 全仓只有 `git_workspace.rs:512`（强制推送）是真的 `dangerous: true`
- **后果**：`git commit`（INJ-1 的落地点）、GitHub 建 issue / 合并 PR / 发 release、任意 profile 的 POST/PUT/PATCH/DELETE 全部**零人工介入**。README:169 与 `docs/mcp-surface:27` 的「逐次桌面确认」表述与实现不符。
- **测试假象**：`src-tauri/src/mcp_surface_tests.rs:121-123` 用 `confirm::with_auto(Some(false))` 只测了「拒绝」分支，掩盖了「危险标记缺失」。

### INJ-3 · `mail save` 可写任意绝对路径 → 启动目录自启持久化
**严重度：中高（需 MCP 已启用 + 有邮箱授权码）**

- **证据**：`crates/sealbox-core/src/mail.rs:1600-1629` `write_exclusive()` 只校验：绝对路径、无 `..`、父目录存在、目标不存在。**没有任何目录白名单**。
- **攻击链**：`mail read` 取附件内容（模型可控来源）→ `mail save` 写到 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\`（父目录存在、目标不存在 → 通过）→ 下次登录执行。
- **附带**：`src-tauri/src/mcp.rs:904` 成功时把**完整绝对路径回显**给模型，便于模型试探文件系统布局。
- **现状测试**：`mail.rs:2492-2506` 只测了「不覆盖」和「拒绝 `..`」，测不到目录限制。

### INJ-4 · 扩展消息总线未校验发送方 → 页面可驱动填充
**严重度：中（需同源页面，或扩展内部 postMessage 回退路径被触发）**

- **证据**：
  - `extension/content.js:94-101` 监听 `window` 的 `message` 事件，只校验 `e.source === window` + `data.source === "sealbox-overlay"` + `data.type === "fill-tab"`，然后 `chrome.runtime.sendMessage({type:"fill-tab", id: data.id})`。**页面脚本可以原样伪造这三个字段**。
  - `extension/background.js:1146` `chrome.runtime.onMessage.addListener` 的 handler **不校验 `sender.id === chrome.runtime.id`**。
  - `extension/background.js:843-851` 存在 `window.postMessage(..., "*")` 回退（当 `chrome.runtime.sendMessage` 不可用时）。
- **已核实的收敛条件**（决定严重度，不要高估）：
  1. 回退分支运行在 ISOLATED world（`background.js:387` `executeScript` 默认 world），页面看不到 `sealbox-overlay` 这个常量，猜不到 magic 串。
  2. `fill-tab` 的 `id` 必须是真实条目 ID，页面拿不到。
  3. `fillTab` 内部会按 origin 重新匹配（`fill.rs` `match_websites`），跨站填充不成立。
  - **所以当前可被利用的现实路径是**：同源钓鱼页（如 `/reset-password`、被注入的同源子页）配合已知条目 ID 才能触发。**不是**任意站点可填。
- **仍然要修的理由**：这三道是「偶然的」而非「设计的」防护；一旦回退分支改成 MAIN world 或 magic 串被顺手写进文档，就变成任意站点可填。

### INJ-5 · `ca_bundle_path` 可指向任意本地文件（读取原语）
**严重度：低**

- **证据**：`src-tauri/src/profile_http.rs:447-454` → `crates/sealbox-core/src/certificate.rs:137-161`，只校验「是文件 / 可读 / UTF-8 / 长度上限」，无路径白名单。
- **为何是低**：模型不能设置该字段（`profile_http.rs:168-174` 的 `transport_override_name` 拦截），只有本机 UI 用户能填；解析失败只返回固定错误串，不泄露文件内容。
- **顺带发现的真问题**：CA bundle 在 https 分支是「公共根 + 自定义」（`profile_http.rs:459-468`），在 mTLS 分支是「仅自定义」（`:470-490`）——**语义不一致**，属于配置注入类的错误行为，建议一并修。

## 二、明文出库 / 外传（EXF）

### EXF-1 · `redact` 前缀名单存在盲区，非 GitHub 类 Token 原样透给模型
**严重度：中高**

- **证据**：`crates/sealbox-core/src/redact.rs:14-19` `token_like()` 只匹配 `ghp_` / `github_pat_` / `gho_` / `sk-` / `AKIA` / `fill_` / `sbx_` / PEM。
- **盲区**：GitLab `glpat-`、Stripe `sk_live_`/`rk_live_`（注意 `sk-` 是连字符，`sk_live_` 是下划线，**不匹配**）、Terraform `atlasv1.`、AWS Secret Access Key（无 `AKIA` 前缀）、Slack `xox[baprs]-`、Google `AIza`、JWT `eyJ...`、QQ/Gmail OAuth refresh token。
- **影响路径**：`http_call` 返回最多 64 KiB 完整响应（`mcp.rs:1237-1241`），经 `redact_tool_text` → `credential_mcp::redact_value`（`credential_mcp.rs:113-128`）。精确替换只能命中「条目里原样存的 secret」，**派生形式**（base64、URL 编码、JWT 里的 claims、分片返回）一律漏。所以非 GitHub 平台返回的 token 会被模型完整看到。
- **已核实的收敛条件**：`secrets` 集合来自 `redact::secrets_from_payload`（`redact.rs:41+`），对本条目存的 secret 做精确替换，这部分是可靠的。问题只在「未登记的第三方 token 形态」。

### EXF-2 · 同步快照的 `device_id` / `written_at` 明文上传远端
**严重度：中**

- **证据**：`crates/sealbox-core/src/sync.rs:911-925` `SyncFile { blob, device_id, written_at }`。
- **影响**：远端（WebDAV/S3 托管方）可枚举设备指纹与同步频率，并据此选择旧快照回放（无单调版本号）。不是「秘密泄露」，但是**可以向远端推断使用者身份与行为**的元数据泄露。
- **附带**：`sync.rs:815-823` 同步密钥是 `SHA-256("sealbox-sync-v1\0" || secret)` 而非 KDF，弱口令可被远端低成本爆破 → 进而解出全库。这条同时是 EXF（让远端能解开）与密码学问题。

### EXF-3 · 手机端 reveal/copy 不进审计（泄露的「事后不可追溯」）
**严重度：中**

- **证据**：`src-tauri-mobile/src/commands.rs:480-490`（`reveal_secret`）与 `:500-530`（`copy_secret`）**没有 `audit(...)` 调用**；桌面 `commands.rs:776-793`、`:742-773` 都有。叠加手机端无 `list_audit` 命令。
- **影响**：秘密外流（人为翻看、被他人借用设备）在手机端完全无痕迹，无法事后判定泄露面。

### EXF-4 · 扩展 `lastFilled` / `pendingSave` 明文副本无严格 TTL
**严重度：中低**

- **证据**：`extension/background.js:235-252` `rememberFill` 写入 `chrome.storage.session` 的 `lastFilled`（含 `username`+`password`）无 TTL；`fill-logic.cjs:2` 的 pending 是 5 分钟。`manifest.json` 的 `storage` 权限 + 这些副本对扩展内任意脚本可读。
- **影响**：与 README:92「明文只暂存在 `chrome.storage.session`」的表述有落差——「会话存储」不等于「短暂」，它跨标签页存活直到浏览器关闭。

### EXF-5 · Windows 剪贴板历史/云同步会把密码抄走
**严重度：中**

- **证据**：`src-tauri/src/clipboard.rs:62-67` `clear()` 只是 `set_text("")`；全仓无 `ExcludeClipboardContentFromMonitorProcessing` / `CanIncludeInClipboardHistory=0` 处理。
- **影响**：Win+V 历史与微软账户剪贴板同步会留存密码明文，`20 秒清空` 只清当前剪贴板，**清不掉历史与云端副本**。这是「本机外传」里最容易被用户实际踩到的一条。

### EXF-6 · 局域网 MCP 监听（能力本身即外传通道）
**严重度：高（但属产品决策，不是代码 bug）**

- **证据**：`src-tauri/src/mcp.rs:19-131`、`commands.rs:1610-1663`、UI `src/App.vue:2877-2896`；而 `README:68/91/134/179` 四处都写「只监听 127.0.0.1」。
- **影响**：一旦开启，同网段任意主机凭 Token 即可 `vault_list` 枚举、`http_call` 用凭据对外发请求、`git` 在宿主机执行（叠加 INJ-1）、`mail save` 写宿主任意目录（叠加 INJ-3）。**这是所有 INJ 条目的放大器**。无 TLS、Token 长期有效。

## 三、复核后判定「不是问题」的候选（避免误修）

| 候选 | 判定 | 理由 |
|---|---|---|
| UI 渲染用户可控 HTML | **不成立** | `src/` 无 `v-html`；唯一 HTML 渲染是邮件正文 `App.vue:3170` 的 `iframe srcdoc`，配 `sandbox="allow-same-origin"`（无 `allow-scripts`）+ CSP + 属性剥离（`mail-html.ts:5/35/113/182/242`），并有 25 个测试 |
| CSV 公式注入 `=cmd` | **不成立（当前）** | `csv.rs` 导入不写回表格、不导出到 Excel 公式上下文；移动端 spec 已明确取舍 |
| SQL 注入 | **不成立** | `vault.rs` 全走 rusqlite 参数绑定；搜索是 `LIKE` 绑定参数 |
| `sbx_`/`fill_` Token 格式弱 | **不算泄露** | UUIDv4 = 128 bit，熵足够；问题在生命周期（永久）不在可预测性 |
| 扩展 `postMessage` 回退「任意站点可填」 | **高估了** | 见 INJ-4「已核实的收敛条件」，ISOLATED world + 未知条目 ID + origin 复匹配三重收敛 |

## 四、建议的修复方案（待确认）

按「链路上游优先」排序。前两条是所有注入项的放大器，先修。

| # | 对应条目 | 方案 | 代价 |
|---|---|---|---|
| F1 | INJ-2 | 给 `git_confirm_payload` 与 profile 写操作真实设置 `dangerous: true`，让确认真正弹出；补一条测试断言「危险操作必须弹窗」，替换掉现在用 `with_auto` 掩盖的写法 | 交互变多，需要一次 UI 文案调整 |
| F2 | INJ-1 | `rel_path()` 拒绝 `.git/` 前缀（hooks/config/info/objects）与 `.github/workflows/`；`git add -A` 前预检被暂存文件，命中即拒绝并列名单 | 极少数合法场景（故意改 CI）需用户手动做 |
| F3 | INJ-3 | `mail save` 增加目标目录白名单：默认只允许用户当场用文件对话框选定的目录；拒绝系统目录、启动目录、Sealbox 自身目录；回显路径改为仅文件名 | 需要一次 UI 改动（选目录） |
| F4 | INJ-4 | `onMessage` 校验 `sender.id === chrome.runtime.id`；删除 `window.postMessage` 回退，改走 `chrome.runtime.sendMessage` 必须路径；`content.js` 的 `message` 监听改为校验一次性随机 nonce | 需同步改 overlay 注入代码 |
| F5 | EXF-1 | `token_like()` 补齐 `glpat-|sk_live_|rk_live_|atlasv1\.|xox[baprs]-|AIza|eyJ[A-Za-z0-9_-]{10,}`；对高熵长串（≥32 字符、字符集熵高）做保守遮罩 | 可能误遮正常长 ID，需调阈值 |
| F6 | EXF-5 | 剪贴板写入时设置 `CanIncludeInClipboardHistory=0` 与 `ExcludeClipboardContentFromMonitorProcessing`（Windows 私有格式）；`clear()` 改为不留空串 | 仅 Windows 分支 |
| F7 | EXF-2 | `device_id` 移入加密 blob；给快照加单调 `revision` 防回放；同步密钥改 Argon2id | 涉及同步格式版本升级，需兼容旧快照 |
| F8 | EXF-3 | 移动端 `reveal_secret`/`copy_secret` 补 `audit(...)`，并补 `list_audit` 命令 | 低 |
| F9 | EXF-4 | `lastFilled` 加严格 TTL（≤60 秒）并在填充完成/页面卸载时清除 | 低 |
| F10 | INJ-5 | mTLS 与 https 分支的 CA bundle 语义统一为「公共根 + 自定义」；`ca_bundle_path` 限定为对话框选定过的路径 | 低 |
| F11 | EXF-6 | **产品决策**：要么删掉局域网监听（回到 README 承诺），要么把能力写进 README 并强制 TLS/短时 Token | 需拍板 |

**建议本轮只做 F1–F6 + F8/F9**（注入链闭环 + 最直接的泄露面），F7 涉及同步格式兼容，F11 需产品决策，单独排期。
