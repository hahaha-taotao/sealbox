# Sealbox 当前不足审计（2026-11-12）

审计对象：`master` @ `c5f7916`（v0.18.1）。只读审计，未修改任何产品代码。

审计切面：安全面、产品功能与桌面体验、移动端与跨平台一致性、工程质量与发布流程。
所有结论均附 `文件:行` 证据；标注「已复核」的条目由 Lead 独立验证过。

---

## 0. 一句话结论

**加密管线和「固定请求 profile」这条 MCP 主路径做得扎实**（AES-256-GCM、Argon2id、UAID 白名单、PublicResolver 防 DNS 重绑定、确认期间不持锁且批准后复校验），真正的不足不在密码学，而在三处：

1. **产品承诺与代码行为不一致** —— 主密码、剪贴板、写操作确认、局域网监听四件事，README 说的和代码做的不一样。
2. **跨端（桌面 / Android / 扩展）的行为分叉** —— 同一操作两端规则不同，且手机端测试从未跑过、审计日志缺失。
3. **发布流程不能保证「要么都有、要么都没有」** —— 与 AGENTS.md「必须同时产出两端」的硬约定不符。

## 1. P0 · 必须优先处理（承诺失真 / 数据风险）

### P0-1 主密码在「本机已登录会话」意义上已失效（Windows）
- **证据**：`src-tauri/src/commands.rs:156-183` `sync_auto_unlock_credential` 每次解锁都无条件 `save_dek(dek)`；`src-tauri/src/secure_store.rs:118` 用 `CRED_PERSIST_LOCAL_MACHINE` 把 32 字节 DEK 写进 Windows 凭据管理器。清除 DEK 的路径只有 panic hook、解锁失败、改主密码三处。
- **后果**：本机任何以同一用户身份运行的进程（窃密软件、被投毒的构建脚本、RDP 会话）都能 `CredReadW` 拿到 DEK 解出全库，**不需要主密码，也不需要 Sealbox 在运行**。README 首页把产品定义为「主密码解锁」，实际只防「拿到文件但没有本机用户会话的人」。
- **已复核** ✓
- **方向**：产品必须先回答「主密码防谁」。若要保留自动解锁，需默认关闭 + 明示风险，并在安全模型里用同等显著度写出这一前提。

### P0-2 「写操作会逐次确认」是空壳，实际全部静默执行
- **证据**：`src-tauri/src/confirm.rs:127-137`，`ask_payload` 在 `payload.dangerous == false` 时**直接返回 true**；而 `src-tauri/src/profile_http.rs:125-140`、`http_profiles.rs:359-377` 构造的所有写操作确认全部是 `dangerous: false`。全仓只有 git 强制推送（`git_workspace.rs:512`）会真正弹窗。
- **后果**：GitHub 建 issue、合并 PR、发 release、任意 profile 的 POST/PUT/DELETE、git commit/push 全部零人工介入。README:169 与 `docs/mcp-surface:27` 的「逐次桌面确认」表述与实现不符。`mcp_surface_tests.rs:121-123` 用 `with_auto(Some(false))` 测到了「拒绝」，反而掩盖了这个事实。
- **已复核** ✓
- **方向**：要么真的做确认，要么把文案改成「默认放行、不可撤回」，并在 MCP 页显示「本次会话已自动执行 N 次远端写操作」。

### P0-3 手机端新建网站条目绕过重复检查（跨端行为直接矛盾）
- **证据**：`src-tauri-mobile/src/commands.rs:393` `.upsert_entry_with_duplicate_policy(&dek, input, true)` —— `allow_duplicate` **硬编码 true**；桌面 `src-tauri/src/commands.rs:523` 是 `allow_duplicate.unwrap_or(false)`，默认拦截。手机端还缺 `find_website_duplicates`，连提示能力都没有。
- **后果**：同一网站账号在桌面被拦住，在手机上静默写入第二条；随后同步推上去，桌面改密/删除容易改错对象。
- **已复核** ✓
- **方向**：`allow_duplicate` 升为两端统一契约，移动端命中冲突时弹「已存在，仍要新建？」。

### P0-4 发布流程可能只发出「半套产物」，违反 AGENTS.md 硬约定
- **证据**：`.github/workflows/release.yml` 中 `release`(L59-65) 一旦成功即 `releaseDraft: false` 公开 Release，而 `linux`(L75) 与 `android`(L169) 都是 `needs: release` 的兄弟 job，二者并行且在数百行之后才上传产物；没有任何 `if: always()` 的收尾校验 job。
- **后果**：Android 或 Linux 任一 job 失败（签名、NDK、SDK 版本漂移），`releases/latest` 上就是一个只有 Windows 资产的正式版，且 `latest` 已被抢占；移动端用户永远拿不到更新，也没有任何提示。
- **方向**：改为两阶段 `build → publish`（全部走 `releaseDraft: true`，末尾统一转正），或加 `verify-all-platforms` 收尾 job，缺任一平台即转回 draft 并 fail。

### P0-5 Android 端 21 个测试从未被执行
- **证据**：CI 中 `cargo test --manifest-path src-tauri/Cargo.toml` 只出现在 `release`(L46) 与 `linux`(L114)，`android` job 没有任何测试步骤。逐 crate 统计 `#[test]`：core 150 / src-tauri 234 / **mobile 21**。
- **后果**：`src-tauri-mobile` 约 2900 行独立胶水（commands 1191 / update 522 / saf 295 / auto_sync 220 / transfer 200）改坏了 CI 不会红；而 README 宣称两端同版本、同构发布。
- **方向**：CI 加 `cargo test --workspace`（或 `--manifest-path src-tauri-mobile/Cargo.toml`）作为独立 job，并让发布 job 依赖它。

## 3. P2 · 值得排期

- **KDF 参数偏低**：`crypto.rs:11-13` `m=19_456 / t=2 / p=1`，且从文件读取时无下限校验（`vault.rs:420-425`），无升级路径。
- **解锁失败无限速**：`session.rs:61-64` 上限 2 秒，`failed_unlocks` 不落盘、不显示。
- **fill token 永久有效**：`fill.rs:452`，扩展存 `chrome.storage.local`。
- **`.svbak` 备份口令无强度门槛**：`backup.rs:59-83` 无最小长度，而主密码要求 ≥10 位（`vault.rs:310-312`）。
- **mTLS 与 https 两处 CA bundle 语义不一致**：`profile_http.rs:459-468` 是「公共根 + 自定义」，`:470-490` 是「仅自定义」。
- **`ca_bundle_path` 可读任意本地文件**：`certificate.rs:137-161` 无路径白名单。
- **MCP 审计粒度不足**：`mcp.rs:749-788` 不记收件人/主题/附件名，`mcp.rs:1053-1108` 只记 path，无法回答「推了哪个分支、改了哪些文件」。
- **TOTP 仅 SHA1/6 位/30 秒**：`totp.rs:111-114`；复制时无倒计时提示（`App.vue:1272`）。
- **全量渲染 + N+1**：`vault.rs:1040` 每条一次 `tags_for`；搜索是 5 个 `LIKE '%q%'` 全表扫描（`vault.rs:948-968`），无 FTS5。
- **Android 剪贴板**：`clipboard.rs:52-160` 未设 `EXTRA_IS_SENSITIVE`（Android 13+ 预览会显示明文），`clear()` 写空串而非 `clearPrimaryClip`。
- **`install_mobile_update` 取消安装也会锁库**：`commands.rs:672-681`。
- **auto_sync 无网络感知**：`auto_sync.rs` 内存 `Instant` + 1 秒轮询，流量/电量不可预期，失败只写 settings 静默。

## 6. 已声明的设计取舍（不建议按缺陷处理，但建议把代价写重）
