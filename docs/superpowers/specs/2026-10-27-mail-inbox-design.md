# 只读邮箱收件箱 — 设计

日期：2026-10-27
状态：待审阅
产品：Sealbox（印盒）

## 1. 目标

删掉测试用的内置助手。用金库里已有的邮箱授权码，只读打开 QQ 和 Gmail 的收件箱：先看最近 50 封的列表，点开再取纯文本正文。统计、报销归类和下载凭证不在这一版。

## 2. 已确认决策

| 项 | 选择 |
|---|---|
| 助手 | 页面、命令、`assistant.rs` 和 README 里的当前说明全部删除；旧的设计文档保留不动 |
| 入口 | 侧栏原「助手」位置改为「邮箱」 |
| 账号 | 只连接 `provider` 为 `qq` 或 `gmail` 的 `mail_auth` 条目 |
| 协议 | Rust 后端现连 IMAP，rustls，993 |
| 主机 | QQ 固定 `imap.qq.com`，Gmail 固定 `imap.gmail.com`；不接受调用方传入主机 |
| 范围 | 每个账号只看 `INBOX`，每次 50 封；用更小的 UID 再取更早的 50 封 |
| 正文 | 点开才取；优先纯文本；只有 HTML 时转成纯文本 |
| 持久化 | 不把邮件写入数据库或磁盘 |
| 副作用 | 不发信、不删信、不改已读、不下载附件 |
| 平台 | 桌面和 Android 共用同一套命令和页面 |

163、Outlook 和「其他」仍出现在账号列表里，显示「首版不支持」，不发起连接。

## 3. 架构

新增只读模块 `src-tauri/src/mail.rs`。授权码只在已解锁的金库会话里读取，不返回前端，不写入审计详情，不出现在错误字符串里。

打开邮箱使用 `EXAMINE INBOX`，不用 `SELECT`。取正文使用 `BODY.PEEK`，避免服务器把信标成已读。列表只取信封和正文结构，用正文结构判断有没有附件，不取附件字节。

三个命令：

- `mail_accounts`：返回条目 id、标题、邮箱地址、服务商、是否可连接。没有授权码。
- `mail_list`：参数为条目 id，以及可选的「比这个 UID 更早」；返回最多 50 封。每封包含 UID、发件人、主题、时间、是否有附件。
- `mail_body`：参数为条目 id 和 UID；返回纯文本。单封超过 200KB 时截断，并在结果里标明已截断。

每次命令单独连接，用完即断开，不在内存里保留 IMAP 会话或正文缓存。连接超时 20 秒。切换账号时不混用另一个账号已经显示的列表或正文。返回给界面的正文按 UTF-8 字节截到 200KB。

审计只记录动作和条目 id，不记录主题、发件人或正文。

## 4. 界面

金库未解锁时，沿用其他页面的锁定状态，不能拉信。

解锁后的邮箱页分三块：

- 左侧列出邮箱授权码。QQ 和 Gmail 可选；其余变灰并写「首版不支持」。
- 中间是当前账号的收件箱：发件人、主题、时间，有附件时显示「有附件」。空收件箱写「收件箱是空的」。底部是「加载更早」；没有更早的信时禁用。
- 右侧是正文。未选择时是空状态。正文是纯文本，不渲染 HTML。

没有写信、回复、删除、标已读或下载附件。加载中禁用会重复发起同一请求的按钮。窄屏改成上下排列：账号、列表、正文。

静态效果见 `docs/prototypes/mail-inbox.png`。

## 5. 错误处理

失败时界面显示固定的中文说明，不展示授权码、服务器原始错误或邮件内容。

| 情况 | 界面 |
|---|---|
| 授权码错误，或 IMAP 未开启 | 登录失败，请检查授权码和 IMAP 是否已开启 |
| 超时或网络中断 | 连接超时，请稍后重试 |
| 服务商不支持 | 账号保持灰色，不连接 |
| 正文超过 200KB | 显示前 200KB，并注明已截断 |
| 抽不出文本 | 这封邮件没有可显示的文本 |

列表已经加载后再失败，不清空已有邮件。「加载更早」失败时保留当前列表，并允许再试。

## 6. 测试

不连接真实邮箱。用固定 IMAP 响应样本覆盖：

- `qq` / `gmail` 映射到规定主机，其他服务商不可连接
- 最近 50 封，以及比给定 UID 更早的下一页
- 主题解码
- 是否有附件
- HTML 转纯文本，以及抽不出文本的结果
- 任意错误字符串都不包含授权码

界面不另写浏览器自动化测试，按原型人工看。

## 7. 明确不做

- 把邮件、信头或正文写入本地库
- 下载或打开附件
- 报销统计、发票识别
- 发信、删信、移动、标已读
- 163、Outlook、自定义 IMAP 主机
- 文件夹切换、搜索、联系人
- 保留或改造内置助手

这些留给后续规格，不在本版实现时顺手加上。
