## 1. 首版目标与范围

用户在 Sealbox 桌面端查询一个 ERP 业务项目，核对签约客户、实际使用方、项目成员、成本资料及 Jira 任务。用户可将项目纳入「我的项目」，保存本地客户关联、Jira 查询范围和指定任务，下次从同一项目继续查看。

| 纳入本次查询 MVP | 沿用上位方案另行实施 |
| --- | --- |
| 桌面查询、详情、已纳入项目与手动刷新 | 模板、排程、甘特图、节点任务关联、提醒 |
| ERP 项目、客户角色、成员和 Jira 任务的只读展示 | 服务单、发票、报销或付款提交、多人协同 |
| 本地客户关联、项目简称自动匹配、手动 Jira 范围与本地补充任务 | 费率估算、分摊、汇率换算、财务对账 |
| ERP 项目预算、成本及分项的只读展示、缺项状态和字段追溯 | 完整成本接入仍属上位方案阶段 C |

成本区随查询 MVP 提供，按 ERP Project 项目级快照展示已核实的金额字段。字段为空或不可读时展示对应状态。原型真实样本也用于来源回归。个人工作区以本地加密存储和备份为准。Android 的兼容目标为保留项目扩展数据，查询入口仅在桌面提供。

## 2. 桌面 MVP 流程

1. 解锁后进入「项目 → 查询」。选择已授权的 ERP 来源，按项目编号、项目名称或客户名称查找。首版以精确匹配为基线。客户结果展开可见的关联项目，并标注「签约」或「实际使用方」。详情预览无需先纳入。查询结果包含项目编号、名称、ERP 状态、可见的客户角色、来源与数据时间。
   左侧项目列表按 ERP 签约客户 ID 分组，显示客户名称和当前匹配的项目数。默认展开，支持折叠。搜索时展开命中的组，清空搜索后恢复原折叠状态。缺少签约客户的项目归入「未填写签约客户」。
2. 打开详情，查看「概览 / 成本 / 人员 / Jira」。未纳入项目可查看平台数据。点击「纳入我的项目」后获得本地项目 ID，重复操作打开已有项目。本地编辑入口放在详情内。
3. 在概览查看「ERP 客户」与「本地客户关联」两列。选择角色后可关联当前 ERP 来源内的客户记录，或补充一条明确标为「手工录入」的本地名称。确认时展示角色、对象及来源。调整或移除本地项后，ERP 列继续显示最近可见的原值和时间。
4. 在「成本」用子导航在「预算与成本 / Jira 项目成本 / 工时与出差」三视图间快捷切换，默认「预算与成本」；只渲染当前视图。详情顶部依次展示项目合同额、项目预算、总成本。预算差额在预算对照中展示。项目表头省略 Jira 简称。预算视图展示分项对照与差额。「Jira 项目成本」按 Jira 项目汇总当前 ERP 项目已关联任务的研发工时和开发成本，只显示项目小计及合计。三个视图通过子导航切换。「工时与出差」以局部可滚列表展示 Hour 12 笔明细，子导航在明细滚动时仍可达，不锁整页高度。项目级快照按整项目展示。分期金额、币种筛选及税口径分组待来源核实。
5. 在「人员」查看 ERP 项目指派人、项目成员、客户负责人。Jira 任务的经办人在任务行展示。姓名相同的人员按其来源及身份分别展示。
6. 「Jira」默认显示 ERP 已关联与本地补充任务的去重列表。项目与状态均为紧凑复选下拉：未选时显示「全部项目 / 全部状态」，有选时显示名称（少选）或数量（多选），各自可清空。选项来自「范围配置」中自动及手动配置的 Jira 项目，以及当前可用状态。项目多选取并集、状态多选取并集，两者与关键词同时生效；勾选过程中菜单保持打开，支持键盘操作。切换项目筛选时尽量保留仍出现在新可用集合中的状态。「按 key 精确补充」仍在任务页。
7. 从「我的项目」重新打开详情。刷新可按来源或分区执行，刷新结果保留上次成功时间、此次状态和可见结果。一处分区失败时，其他分区仍可查看。

## 3. 对象与关键字段

字段为产品契约。实际字段映射以已确认的来源目录为准。

| 对象 | 关键字段与约束 |
| --- | --- |
| 来源绑定 | `source_binding_id`、工作区、平台、规范化站点、已验证账号范围、凭据引用、授权 revision、能力状态。站点保留有业务意义的实例路径。凭据仅保存引用。 |
| ERP 项目 / 本地项目 | ERP 项目保存来源、字符串远端 ID、编号、名称、状态、开始日期、计划上线、计划交付、实际结束和快照时间。本地项目保存 UUID、工作区、ERP 引用、**项目简称**（可空；用于自动匹配 Jira 项目 key）、归档状态、revision、创建和更新时间。工作区内同一 ERP 站点、账号范围及项目 ID 唯一。默认示例简称 `XKRL`。 |
| ERP 客户角色快照 | ERP 项目引用、角色（签约 / 实际使用方）、字段名、目标模块、远端 ID、可用名称、读取状态与成功时间。项目指向 `Contacts` 时按联系人显示，确认关联后才可展示其所属账户。 |
| 本地客户关联 | 本地项目 ID、角色、ERP 客户引用或手工名称、说明、变更时间、revision。MVP 每个角色最多一条当前本地关联，替换需要显式确认。签约和实际使用方可指向同一客户，仍保留两条角色关系。手工名称可用于本地查看，ERP 反查以可见来源记录为准。 |
| 人员 | 人员类别、显示名、来源/模块/远端人员 ID（可用时）、ERP 成员关系 ID、角色、参与状态、起止日期、数据时间。ERP 指派人、ERP 客户联系人、项目成员和 Jira 经办人保留各自身份；缺稳定人员 ID 时仅作为原记录的显示信息。 |
| Jira 任务 | 来源、稳定 issue ID、当前 key、标题、Jira 项目 ID、状态及状态类别（可用时）、经办人、远端更新时间、本地读取时间、可见性。项目同样使用稳定 ID，key 供用户识别。 |
| ERP Jira 关联快照 | ERP 项目引用、JIRATask 来源记录、任务 key、Jira 链接、研发工时、开发成本、读取时间及 Jira 精确查验状态。按 ERP JIRATask.`cf_project_id` 读取平台既有关联。界面默认进入「项目任务」列表，标「ERP 已关联」，不写入本地精确关系，也不再提供重复绑定。 |
| Jira 范围关系 | 有效范围 = **简称自动匹配 ∪ 手动补充**，按 Jira 项目稳定 ID 去重并标注来源（`auto` / `manual`，可并存）。自动匹配：将项目简称 `trim` 后转大写，对已授权来源内的 Jira 项目 key 做 substring 包含判断；空简称不产生自动项。手动补充：用户显式添加的已授权 Jira 项目。每条关系保存本地项目 ID、Jira 来源、Jira 项目稳定 ID、项目 key/名称快照、来源标记、创建时间。原型可将未解析的手输 key 标为「待验证」演示；**正式版必须解析到当前授权来源的稳定项目 ID，否则拒绝保存。** |
| Jira 本地补充任务关系 | 本地项目 ID、Jira 来源、稳定 issue ID、key 快照、创建时间。用于 ERP 未挂但属于本项目的任务，可独立于范围存在；界面标「本地补充」。与 ERP 既有关联去重并集后计入页签任务数。后续计划节点与任务的关联沿用上位方案中的节点级关系。 |
| ERP 项目金额快照 | ERP 项目引用、来源绑定、源模块、字段名、字段原值、定点金额、读取状态及时间。币种和含税口径按已核实的来源元数据展示。 |
| 查询状态 / 缓存 | 绑定账号、查询类型和筛选条件、请求时间、上次完整成功时间、分区状态、分页完成度和警告。保留单项读取时间；缓存内容加密。 |

### 3.1 简称匹配与两类本地 Jira 关系的写入行为

- **简称自动匹配**：保存/修改项目简称后立即重算。规则为 `normalize(short) = trim(short).toUpperCase()`；若结果为空，自动集合为空，有效范围只含手动项。否则在已授权 Jira 项目中选取 `projectKey.toUpperCase().includes(normalize(short))` 的项目。当前已核实带任务的项目 key 为 `XKRL`、`XKRLWXM`；`XKRLWXV` 可作为匹配规则示例或待验证模拟输入，本样本无任务。编辑简称不改写手动补充列表，只改变自动集合。
- **手动补充与并集**：手动添加写入手动集合；与自动命中重合时幂等（同一 Jira 项目 ID 只保留一条有效范围），来源标记可同时含 `auto` 与 `manual`，并提示「仍在范围内，因简称命中 / 手动保留」。移除手动项后若简称仍命中，该项目留在自动范围并说明原因；仅当自动与手动都不命中时才退出有效范围。
- **任务筛选与范围配置**。简称及自动或手动范围在「范围配置」编辑。项目复选下拉的可选项为有效范围并集；未选项目等于「全部项目」。状态复选下拉的可选项为当前所选项目（或全部项目）下的可用状态并集。项目筛选取并集，状态筛选取并集，再与关键词同时生效。切换项目筛选时尽量保留仍可用的状态，而不是一律清空。范围配置变化后，已选但不在有效范围内的项目自动忽略，并同步收紧状态筛选与触发器文案，保持 UI 与过滤一致。正式版按已授权 Jira 项目的工作流配置获取各任务类型的可用状态，按状态 ID 去重；离线原型使用现有 Jira 适配器的内置状态预设及已核实快照状态。正式版绑定目标必须解析到当前授权来源的稳定 ID。
- 范围唯一键为「本地项目 + Jira 站点/账号范围 + Jira 项目 ID」。本地补充唯一键为「本地项目 + Jira 站点/账号范围 + issue ID」。事务内校验，两次同样的添加返回同一关系。并发编辑使用 revision 检查。
- 移除手动范围只删手动标记；自动命中不受影响；**真实项目任务列表（ERP ∪ 本地补充）不变**。解绑本地补充只删该任务关系；若任务仍落在有效范围，候选筛选里继续可见。ERP 既有关联不可通过本地解绑移除。重复移除返回已解绑。各操作仅写本地关系。
- 任务改 key 或移到另一个 Jira 项目后，本地补充跟随稳定 issue ID；范围是否命中由任务当前所属项目与当前简称/手动集合决定。任务不可见时保留本地补充关系，显示该来源状态。
- ERP 和 Jira 各自独立选择授权来源。站点或账号范围变化时使用新的来源身份。同名账号、相同项目 key 或 issue ID 不能触发自动换绑。旧来源选中不可用时保留关系的待重绑状态，重绑必须显式确认并验证身份。旧账号缓存仅在原来源账号和有效授权下可读。

- 项目预算和总成本直接读取 ERP 总值。此样本的预算分项合计为 25100，成本分项合计为 21552.73，两者分别与对应总值吻合。该关系只用于本项目回归。其他项目总值缺失时保持未知，分项可独立展示。
- 「预算减总成本」由界面使用定点十进制计算。此项目为 25100 − 21552.73 = 3547.27，两个操作数均可读才计算。「项目预算毛利润」单独展示 ERP `cf_9758` 原值 3580.87。两个数值分别标注名称和来源，禁止互相替代。
- ERP `Project` 研发成本分项原值为合同内定制 `cf_9962` 1328.13、合同外定制 `cf_9964` 0、产品优化 `cf_9966` 0、定制缺陷 `cf_9968` 0、产品缺陷 `cf_9970` 25。原值可按字段追溯。JIRATask 开发成本用于本项目来源核对，项目成本仍直接读取 `Project`。
- 成本总览首项显示 ERP `Project` 的项目合同额 `cf_9778`（本样本为 60000）。合同额 `cf_1486` 60000、总回款 `cf_2932` 60000、回款毛利润 `cf_1488` 38447.27 在经营指标中展示。工时和出差量作为工作量展示。经营指标和工作量独立于成本金额。
- 显式 `0` 显示零，ERP 空值、未核实字段、不可读及查询失败各自显示状态。金额以定点十进制保存，明细提供源模块、项目引用、字段名、原值、读取时间与可用的源记录入口。币种、含税口径未知时明确标注，保留来源原值。原始平台统计页面的 UI 分组、公式、费率及独立币种、税口径字段均待核实。`cf_1344` 仅表示 ERP 税费金额。
- ERP `Fee` 有报销、差旅字段及客户、订单、商机外键，目前无直连 `Project` 外键。客户同名不能证明项目归属。报销、付款、费用单据汇总及追溯留在完整成本接入范围。

| --- | --- | --- |
