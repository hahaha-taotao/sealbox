# 浏览器验证码登记与页面识别 — 设计

日期：2026-09-28  
状态：待用户审阅  
产品：Sealbox（印盒）

## 1. 背景与目标

Sealbox v0.2.0 已支持在网站凭据中保存 TOTP 密钥，并在浏览器填充时返回当前 6 位码；扩展只接收验证码，不接收 TOTP 密钥。前提是用户先取得并保存该网站生成的 TOTP 设置。另一些网站会在当前登录页显示短信/邮件验证码文本，用户希望减少复制粘贴。

本设计包含两个相互独立的能力：

1. **TOTP 登记**：用户在启用网站双重验证时，选择二维码图片或提供 `otpauth://` URI；Sealbox 在本机解析并经确认后，将 TOTP 密钥写入所选网站凭据。配置一次后，继续复用已有自动生成与填充链路。
2. **页面可见验证码候选**：浏览器扩展在检测到登录页后，从当前页面可见文本中寻找具有验证码语义上下文的 4–8 位数字。只显示候选和有限来源上下文；用户明确确认后才填入，不自动提交表单。

该功能不会从验证码推算 TOTP 密钥，也不读取操作系统短信、通知、邮箱、浏览器登录库或隐藏页面数据。

## 2. 产品范围与非目标

### 本期包含

- Sealbox 桌面端选择二维码图片并在本机解码。
- Sealbox 桌面端粘贴 `otpauth://totp/...` URI；拒绝 HOTP 及不支持的算法、位数或周期，并复用现有 TOTP 规范化校验。
- 登记前展示可确认的服务名/账号标签和目标金库条目；允许关联现有条目或创建网站条目。
- TOTP 密钥只保存到现有加密金库；扩展与网页 overlay 只拿到当前码。
- 扩展检测登录页后自动扫描可见文本；只在有候选时提示，用户确认后把选中码填入已识别的验证码框。
- 对多个候选分别展示简短上下文以供用户选择；不唯一时不预选、不自动填入。
- 临时验证码候选仅保存在扩展内存中，不写 `storage.local` 或 `storage.session`，不进入日志或统计。

### 明确不包含

- 从当前验证码、用户名、密码、网址或历史验证码推算/破解 TOTP 密钥。
- 读取系统短信、通知、邮件客户端或邮箱网页中的验证码。
- 识别或绕过 CAPTCHA、图片挑战、反自动化验证。
- 自动提交登录表单，自动触发“发送验证码”，或在用户未确认时填入页面可见短信/邮件码。
- 读取隐藏元素、输入框当前值、脚本状态、跨域 iframe 文本或浏览器凭据数据库。
- 自动把二维码/URI 中的账号信息用于覆盖既有凭据；更新关联关系必须由用户确认。

## 3. 用户流程

### 3.1 登记 TOTP

1. 用户在网站的双重验证设置中选择 Sealbox 支持的 TOTP，并在网站端查看配置二维码或 URI。
2. 用户在 Sealbox 的网站凭据编辑/创建界面选择“导入 TOTP”，然后选择二维码图片，或粘贴 `otpauth://` URI。
3. Sealbox 本机解码/解析，执行现有 Base32 和 SHA1/6 位/30 秒约束校验；错误时说明原因，不保存。
4. 确认界面显示服务名、账号标签（如 URI 提供）以及准备关联的 Sealbox 条目。不得显示完整密钥，也不得把密钥写入预览或诊断日志。
5. 用户确认目标条目并保存；目标条目列表显示已有 TOTP 标记。此后日常填充沿用 v0.2.0 流程，无需再次手工输入密钥。
6. 用户可在凭据编辑界面替换或移除 TOTP；替换/移除须明确保存。

### 3.2 页面可见验证码识别

1. 扩展按现有方式检测到登录表单后，检查当前文档的**可见文本节点**，不读取表单值或隐藏 DOM。
2. 仅把 4–8 位连续数字且附近具有验证码语义词的文本片段列为候选。语义词包括中英文的验证码、动态码、校验码、verification code、security code、one-time code、OTP 等。
3. 有候选时在扩展 overlay 显示“发现页面验证码”，候选内容及短上下文由本地扩展直接展示。不要把原始整页文本发送到 Sealbox、远端或日志。
4. 用户点选一个候选并确认后，扩展把该码填入当前页面已识别的可见验证码输入框；找不到输入框时保留候选提示并给出说明，不做其他输入。
5. 若当前凭据已配置 TOTP，原有 TOTP 自动填充逻辑优先；短信/邮件候选不覆盖自动生成的 TOTP。用户仍可显式选择页面候选作为另一来源。
6. 页面导航、标签页关闭、登录页离开、候选过期或扩展锁定/配对失效时，清除内存候选。

## 4. 安全与隐私约束

- 二维码图片解码、URI 解析和密钥规范化都在本机完成；不上传图像、URI、密钥或页面文本。
- 图片导入使用本机文件选择器；先检查文件大小和格式，再解码。不得把二维码原图或解码后的原始 URI 写入临时文件、日志、剪贴板或审计明细。
- URI 粘贴值在界面内存中只保留到解析/确认流程结束；成功后立即清空输入状态。调用错误和调试信息必须经过脱敏。
- TOTP 明文密钥只进入现有金库加密写入路径；前端确认视图只显示脱敏的服务名/账号信息，不显示完整密钥。
- 页面扫描仅访问顶层当前站点中可见文本节点，不读 `input`、`textarea`、`contenteditable` 的值，不扫描隐藏节点、闭合 shadow root 或跨域 frame。
- 候选码仅由扩展 UI 本地显示并经用户确认后填充；不发送给桌面应用，不持久化，不用于自动提交。
- 不支持的二维码/URI、多个冲突参数、无效 Base32、超大图片、页面候选歧义均 fail closed：不给密钥/验证码写入行为。

## 5. 实现边界建议

- **Rust/Tauri 登记入口**：本机选择图片路径及 URI 解析命令；校验大小、格式和 URI 参数；调用已有 TOTP 规范化逻辑；最终复用现有 `create_entry`/`update_entry` 金库加密保存路径。新命令不得返回规范化密钥或完整 URI。
- **二维码解析模块**：独立的 Rust 模块，输入受限图片字节，输出短暂的结构化登记元数据和待保存密钥；不引入网络能力。具体 crate 选择在实施计划阶段根据 Windows 构建兼容性、离线可用性和许可证评估。
- **Vue 登记 UI**：添加文件选择、URI 粘贴、解析状态、目标条目确认和替换确认；解析后仅展示脱敏元数据。错误文案不得回显输入中的密钥/URI。
- **扩展页面扫描器**：独立的纯函数模块接受可见文本片段/DOM 元数据并返回候选；content script 负责可见性和上下文采集，background 负责触发调度，overlay 负责确认与字段填充。候选码不传回 Rust。
- **测试**：Rust 单测覆盖 QR/URI 校验、参数拒绝、大小限制和密钥不回传；扩展单测覆盖语境匹配、数字长度、隐藏/输入值排除、歧义排序、过期清理和确认前不填；集成测试覆盖同屏 TOTP 与页面文本候选的优先级。

## 6. 失败处理

- 图片不能解码、找不到 TOTP URI、URI 格式不支持：提示用户从网站重新导出/截图；不得静默创建空 TOTP。
- URI 中声明非 SHA1、非 6 位、非 30 秒周期：复用既有规则拒绝并说明当前支持范围。
- 目标条目不存在：允许用户明确创建网站条目或取消；不根据 URI 自动覆盖已有账号。
- 页面未找到候选：不显示空提示，不改变当前表单。
- 候选存在但找不到兼容验证码框：提示可复制/手动输入；不把码填入用户名或密码框。
- 多个候选：展示各自短上下文，不默认选中；用户必须确认单个候选。

## 7. 验收标准

1. 用户选择有效 TOTP 二维码图片或粘贴有效 `otpauth://totp` URI 后，可确认并关联到正确凭据；保存后金库仅暴露 `has_totp`，扩展仍只接收当前码。
2. 错误图片、HOTP、无效 Base32、非支持参数及超限文件不会修改金库，且错误信息不泄露密钥。
3. 用户在登录页后，扩展能从可见且有验证码语义提示的 4–8 位文本识别出候选；在确认前不改页面输入。
4. 确认单个候选后，只写入可见、启用、可编辑的 OTP 输入框；永不填入密码框，永不提交表单。
5. 不读取隐藏字段、用户输入值、跨域 iframe、系统短信或邮箱；候选不持久化且不会进入日志。
6. 现有 TOTP 同屏填充/跨页填充行为保持回归通过。
