# 邮箱体验补齐（对标 Sigil）— 设计

日期：2026-11-13
状态：实施中（0.20.0）
前序：`2026-11-12-mail-client-design.md`（0.19.0，只读邮件客户端骨架）

## 1. 这一轮解决什么

0.19.0 把「能收、能看、能搜」的地基铺完了，但日常用起来还差三件事：

| # | 问题 | 用户感受 |
|---|---|---|
| 1 | 每封邮件点开都要新建一次 IMAP 连接、拉一次完整正文 | 点一封邮件要等 1–3 秒，翻着看很折磨 |
| 2 | 列表只保留屏幕上的那一页，没有任何本地留存 | 断网、退出重进、切账号回来都是空白；「加载更早」每次都要重连 |
| 3 | 完全没有「已读」概念，未读数只能靠服务器 `\Seen` | 看过的邮件仍然是未读，文件夹上的数字永远减不掉 |
| 4 | 列表行只显示一行拼接文本，没有发件人/时间层次 | 一屏看不了几封，找不到重点 |
| 5 | 正文没有字号、打印、复制全文，长正文阅读体验差 | 小字商务邮件读起来费劲 |

这一轮把这五件事按 Sigil 的实际体验补齐，**仍然不发信、不回写服务器**。

## 2. 不退让的约束

沿用 0.19.0 的全部只读承诺，并在这一轮显式写死：

- 所有文件夹仍用 `EXAMINE` 打开，正文一律 `BODY.PEEK`。
- **不发送** `STORE` / `COPY` / `MOVE` / `EXPUNGE` / `APPEND`。
- 「已读」只写本地库的 `local_seen` 列。服务器不知道你读过，也不会因为读信把邮件标成已读——这正是密码管理器该有的行为。
- MCP `mail` 工具不新增任何 action；`search` 仍只读本地缓存，不触发联网。

## 3. 缓存层（`mail_store.rs`）

### 3.1 表结构

`mail_messages` 增两列，走幂等迁移（`PRAGMA table_info` 判断后再 `ALTER TABLE`），老库升级不报错：

```sql
ALTER TABLE mail_messages ADD COLUMN local_seen INTEGER NOT NULL DEFAULT 0;
ALTER TABLE mail_messages ADD COLUMN list_snapshot TEXT;  -- 最近一次列表返回的时间
```

`local_seen` 与服务器的 `seen` 分开存：`seen` 是服务器说的，`local_seen` 是本机记录的。界面上的「已读」= `seen OR local_seen`，这样服务器哪天真的标了已读，本地记录也不会互相打架。

### 3.2 新函数

| 函数 | 用途 |
|---|---|
| `list_local(account, folder, before, limit, filter, keyword)` | 本地分页，`filter` 支持 all / unread / attached / flagged，排序 `uid DESC` |
| `cached_list_all(account, before, limit)` | 「全部收件箱」跨文件夹聚合 |
| `set_local_seen(account, folder, uid)` | 打开邮件后本地记已读 |
| `prefetch_candidates(account, folder, limit)` | 正文尚未缓存的最新 N 封的 uid，给预取用 |
| `sweep(account, folder, keep, pins)` | 只保留最新 `keep` 封（默认 300），并额外保留**已取过正文**的行与**星标**行；正文缓存行另有上界，超出按 `body_fetched_at` 最旧先删；**只删本地行，不碰服务器** |
| `local_unread_by_role(account)` | 按角色汇总本地未读 |

## 4. 读取路径

### 4.1 `mail_list`：缓存优先

```
本地有行？
├─ 是 → 立刻返回本地结果（带 list_snapshot 供界面显示「最近更新」），
│        同时后台线程联网拉最新一页写回缓存，完成后发事件
└─ 否 → 联网拉一页（保持 0.19.0 行为），写缓存后返回
```

界面拿到的永远是「马上就有东西」。后台刷新完成后发 `mail-synced` 事件，界面据此更新「最近更新」时间，不打断正在读的邮件。

### 4.2 `mail_body`：正文预热 + 本地已读

- 新增 `markSeen`（默认 `true`）：只要正文返回，就把 `local_seen` 置 1，并把未读数减一（本地乐观更新）。
- 新命令 `mail_prefetch(entryId, folder, limit?)`：对该文件夹正文未缓存的最新 8 封逐封取 `BODY.PEEK[]`（与单封阅读走同一条解析路径，`TEXT` 拿不到 HTML 部件），写进缓存。进入邮箱页时静默调用一次，用户点开时正文直接命中缓存。
- `mail_prefetch` 完全后台化：命令**立刻返回**，工作线程自建连接、只在读写库时短锁，锁从不跨越网络往返；同一 `entryId+folder` 只允许一趟在跑，重复调用被折叠。
- 因此它的返回值是**「这一趟是否入队」**（`1`=已入队，`0`=被正在跑的一趟折叠），不是预热到的封数。真实封数通过 `mail-page-refreshed` 事件的 `bodies` 字段送回。界面不得把它当封数显示。
- 预取失败一律静默，不弹错误。预取**只由界面触发**，MCP 拿不到这个入口。

### 4.3 未读口径（实现为准）

0.19.0 的角标只算 `inbox + archive`，理由是 `sent/drafts/trash` 在服务器上普遍不带已读标记。这一轮把已读搬到本地后，这个理由消失了一半，但口径保持不变：

未读数**一律以 `mail_messages` 实时 `COUNT(seen=0 AND local_seen=0)` 为准**，与「未读」筛选同源。`mail_folders.unread` 降级为服务器直报值，不喂任何用户可见数字。

为什么不取「快照与本地计数取较大值」：服务器报 5 封而本地只缓存 2 封时会显示 5，用户点掉 2 封还剩 3 个**点不掉的底数**，且无法通过任何操作消除。纯实时 COUNT 在缓存不完整时偏小，但偏小会被下一次刷新自动纠正——宁可偏小。

- 侧栏总角标：`inbox + archive` 的未读之和。
- 文件夹旁数字：用 `mail_unread_by_role` 给出各角色自己的数字；`sent/drafts/trash` 也能显示，读一封少一个，不会挂底数。

## 5. 界面（桌面）

### 5.1 列表行

```
┌──────────────────────────────────────────────┐
│▌发件人                     今天 09:12  📎 ★  │
│  主题（未读加粗，已读常规）                    │
└──────────────────────────────────────────────┘
```

- 未读：左侧 3px 强调条 + 主题 600 字重；已读：灰一档、无强调条。
- 时间格式：今天 `HH:mm`、昨天 `昨天`、7 天内 `周三`、更早 `YYYY-MM-DD`。
- 附件与星标用小图标，不做文字标签。

### 5.2 正文工具栏

| 工具 | 行为 |
|---|---|
| 字号 | 小 / 标准 / 大，改写 `buildMailDocument` 的 `fontScale`，只影响显示 |
| 纯文本 / HTML | 正文有两种形态时可切换；HTML 仍走 sandbox iframe |
| 打印 | 把当前正文文档写进隐藏 iframe 调 `print()`，只打印正文 |
| 复制全文 | 复制纯文本正文到剪贴板（复用现有剪贴板超时机制） |
| 显示图片 | 保留 0.19.0 的远程图片开关 |

### 5.3 快捷键

`j` / `k` 上下移动，`Enter` 打开，`u` 或 `Esc` 回列表，`/` 聚焦搜索，`r` 立即收取。焦点在输入框、textarea、contenteditable 或正文 iframe 内时不触发。

### 5.4 缓存态提示

列表顶部一行小字：`离线缓存 · 最近更新 11-13 09:20`。收到 `mail-synced` 或手动收取成功后更新。

## 6. 界面（手机端）

同步 5.1 的列表行、5.2 的字号 / 纯文本切换 / 显示图片、5.4 的缓存态提示；快捷键不做（触屏无意义）。保留现有左滑返回与 SAF 保存附件。

## 7. 命令面变化

两端签名一致，新增三个：

| 命令 | 桌面 | 移动 |
|---|---|---|
| `mail_prefetch` | 有（返回 0/1 表示是否入队） | 有（同） |
| `mail_unread_by_role` | 有 | 有 |
| `mail_list` 的返回语义 | 缓存优先 | 缓存优先 |

`mail_body` 增加可选 `markSeen`，默认 `true`。`mail_unread_count` 签名不变。

MCP：`mail` 工具定义、action 列表、参数白名单**完全不变**。

## 8. 测试

- `mail_store`：本地分页（含 before 游标）、四种筛选、`local_seen` 与 `seen` 合并口径、`sweep` 保留 pin 与 keep、迁移幂等（同一库跑两次 `ensure_schema`）。
- 前端纯函数：相对时间格式化、字号映射，补 `.test.mjs`。
- 只读回归：断言代码里不出现 `STORE` / `COPY` / `MOVE` / `EXPUNGE` / `APPEND` 作为发出的命令。
