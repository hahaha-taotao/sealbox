# 本地凭据金库 — 第一版设计

日期：2026-09-11  
状态：已批准  
产品名：Sealbox（印盒）  
应用 id：`com.sealbox.app`  
对标参考：Sigil 掌玺（https://sigil.ruoyi.plus/），仅借鉴「本地金库」思路与界面视觉，不复制其 AI/MCP 功能集。

## 1. 产品定位

做一个 Windows 桌面凭据金库：给人安全存放网站账号、API Token、SSH/证书；日常用主窗口或全局快捷键复制；可导出加密备份换机。按可发布产品的标准写加密、数据格式和审计，但第一版只给自己用。

它不是 1Password 的云同步密码箱，也不是第一版就做 Sigil 那样的 MCP 代理。第二期再在同一个 Rust 核心上接 MCP，让 AI 调用能力而看不到明文。

一句话：本机金库先做对，印章房以后再接。

## 2. 已确认决策

| 项 | 选择 |
|---|---|
| 谁用 | 先给自己用，架构按能发布写 |
| 平台 | 第一版只做 Windows |
| 条目类型 | 网站账号、API Token、SSH/证书 |
| 存储 | 只存本机；支持加密备份导出/导入 |
| 解锁 | 主密码为根；Windows Hello 为第二把钥匙 |
| 使用方式 | 应用内复制 + 全局快捷键速查；不做浏览器填充 |
| 技术 | Tauri 2 + Vue 3 界面 + Rust 金库核心 |
| 界面 | 借 Sigil 保险库的视觉（白底、图标栏、分类侧栏、表格、类型色标、圆角按钮），不借其功能清单 |

## 3. 范围

### 3.1 第一版要做

- 首次设主密码、日常主密码或 Windows Hello 解锁、手动锁定、空闲自动锁定
- 三类条目的增删改查、搜索、文件夹、标签、置顶
- 列表展示元数据；显示明文有超时；复制主秘密 / 账号；剪贴板 20 秒后清空
- 网站账号可选 TOTP（本地生成 6 位码）
- 新建网站密码时可本机生成密码
- 全局快捷键浮层搜索（默认 Ctrl+Shift+Space）
- 加密备份导出 / 导入（默认合并，覆盖需确认）
- 删除进回收站（侧栏可进），30 天后物理删除；可单条或勾选批量移入回收站，可从回收站还原
- 审计：解锁、复制、显示、导出、导入、删除；不记秘密值
- 主窗口 + 系统托盘；关窗口藏托盘，退出才锁库并清内存
- 首页概览：条数、最近使用、即将过期
- 设置：超时、热键、Hello 开关、剪贴板秒数、备份入口

### 3.2 第一版明确不做

- macOS / Linux
- 云同步、多用户、账号系统
- 浏览器自动填充、向其他窗口注入按键
- MCP Server、AI 对话、能力白名单、Kill Switch 产品化
- 文件加密盘、加密分享包、邮件、MQTT、对象存储、内置浏览器、Git 工作区
- Bitwarden 导入、扫描导入、Have I Been Pwned、试用倒计时
- Token 额度刷新、分页（本地全量列表 + 搜索即可）
- 自动定时备份、备份上传网盘
- 试错 N 次后自动销毁金库

### 3.3 第二期预留（不实现，但接口要留得住）

Rust 核心暴露内部 `VaultService`：按筛选列出元数据、按 id 解密一次、写审计。MCP 将来只调这个接口，不经过前端，也不把明文送进模型。第一版不监听任何本机 HTTP 端口。

## 4. 成功标准

第一版算做成，当且仅当：

1. 设主密码后可创建三类条目，重启后须解锁才能看见列表。
2. 列表、搜索、审计、日志里没有密码 / Token / 私钥全文。
3. 复制后约 20 秒，若剪贴板仍是那条秘密则被清空。
4. 空闲超时或点锁定后，复制和显示都必须重新解锁。
5. 导出备份，在本机清空或新目录导入（合并），条目能对上；Hello 不能解开备份文件。
6. 全局热键弹出小窗，搜到条目回车即复制主秘密。
7. 安装包可在目标 Windows 上安装运行（开发阶段用 `tauri dev` 验证即可）。

## 5. 架构

单个 Windows 进程，两层，中间只走 Tauri `invoke`，不走 HTTP。

```
Vue 3 界面
  主窗口：解锁 / 首页 / 保险库 / 审计 / 设置
  快捷键小窗：解锁或搜索复制
  只接收元数据、脱敏预览、操作结果
        │ invoke
Rust 核心
  会话（数据密钥在内存）
  VaultService（CRUD、搜索元数据、按需解密）
  加密、Hello、热键、剪贴板定时清空、备份、审计
        │                    │
  SQLite（密文+元数据）   Windows Credential Manager
```

三条硬边界：

1. 明文只在 Rust 里短暂出现。前端默认看不到完整秘密；「显示」或「复制」才请求一次。
2. 磁盘无明文。SQLite 存元数据与 AES-256-GCM 密文；数据密钥用主密码派生钥包装，另有一份包装进 Credential Manager 供 Hello。
3. 第二期 MCP 接 `VaultService`，不接前端。

关主窗口 ≠ 退出。托盘仍在，热键才可用。退出或锁定：丢掉内存中的数据密钥、清我们放入的剪贴板。

## 6. 技术选型

| 层 | 选择 | 原因 |
|---|---|---|
| 壳 | Tauri 2 | 包体小；Rust 侧管密钥；与后续 MCP 同进程 |
| 界面 | Vue 3 + TypeScript | 适合这张保险库表格/侧栏；中文社区熟 |
| 样式 | 自研 CSS 变量（色、圆角、字号）+ 少量无样式头的轻量组件 | 对齐参考截图的浅色后台；不引入 Ant Design / Element Plus 整套主题 |
| 数据库 | SQLite + rusqlite，文件在用户数据目录 | 单文件，备份友好；桌面进程不必上 sqlx 异步运行时 |
| KDF | Argon2id | 主密码派生 |
| 加密 | AES-256-GCM，每条独立 nonce | 条目正文 |
| 系统密钥环 | windows-rs / keyring，Credential Manager | Hello 包装钥 |
| Hello | WinRT UserConsentVerifier | 本机生物/PIN |
| 热键 | Tauri global-shortcut | 系统级 |
| 剪贴板 | arboard 或 Tauri clipboard，Rust 侧定时清空 | 秘密不经前端常驻 |

窗口标题、关于页、安装包显示名均为「Sealbox 印盒」。仓库目录可以仍叫「密码管理器」。crate 名 `sealbox`。

## 7. 数据模型

SQLite 文件放在 Windows 用户数据目录（Tauri `app_data_dir`），例如 `%APPDATA%/<app>/vault.db`。

### 7.1 库级元数据（单行 `vault_meta`）

- `kdf`：argon2id 参数（内存、迭代、并行、salt）
- `wrapped_data_key`：主密码派生钥包装的数据密钥
- `hello_enabled`：是否启用 Hello
- `wrapped_dek_hello`：用 `hello_key` 包装的 DEK（Hello 关闭时为空）；`hello_key` 本身只在 Credential Manager
- `schema_version`
- `created_at` / `updated_at`

Credential Manager 条目名 `Sealbox/hello_key`。卸载或关 Hello 时删除该条目。

### 7.2 条目 `entries`

明文列（可搜、可排序、可上表）：

- `id`：UUID
- `kind`：`website` | `api_token` | `ssh`
- `title`：键名
- `account`：关联账号（用户名/邮箱/注释名，可空）
- `url`：网站条目用，可空
- `folder_id`：可空 = 未归类
- `pinned`：置顶
- `expires_at`：可空 = 永不
- `use_count`、`last_used_at`、`created_at`、`updated_at`
- `deleted_at`：非空即在回收站
- `has_totp`：网站条目是否配置了 TOTP（布尔，不存密钥）
- `fingerprint`：SSH 公钥指纹（明文）

密文列（AES-256-GCM，nonce 与密文一起存）：

- `secret_blob`：该类型的秘密 JSON
- `notes_blob`：备注，可空；备注也加密。列表不显示备注全文。第一版搜索**不包含备注**（只搜键名、账号、网址、标签、文件夹）。打开编辑表单时才解密备注。

标签：`tags(id, name)`，`entry_tags(entry_id, tag_id)`。文件夹：`folders(id, name, parent_id)`。第一版文件夹单层（`parent_id` 恒空）。

审计：`audit_events(id, at, action, entry_id, detail)`。`detail` 只含类型、键名、结果，禁止秘密。

回收站：`deleted_at` 起 30 天后，启动或定时清理时物理删除该行（含密文）。

### 7.3 三类 `secret_blob` 明文结构（仅内存中）

**website**

```json
{
  "url": "https://jira.example.com",
  "username": "alice",
  "password": "...",
  "totp_secret": null
}
```

`url`/`username` 与明文列重复一份，解密编辑时用密文为准，列表用明文列。保存时同时更新明文列与 blob。TOTP 密钥只在 blob 里。

**api_token**

```json
{
  "service": "github",
  "account": "octocat",
  "token": "ghp_..."
}
```

`service` 为 `github` | `gitee` | `gitlab` | `custom`。第一版不做 OAuth 刷新、不做额度查询。

**ssh**

```json
{
  "key_type": "ed25519",
  "private_key": "-----BEGIN OPENSSH PRIVATE KEY-----...",
  "passphrase": null,
  "public_fingerprint": "SHA256:...."
}
```

私钥只在 blob。

### 7.4 列表对外 DTO（给前端）

不含任何 blob。字段：id、kind、title、account、url、folder_id、tags、pinned、expires_at、use_count、last_used_at、updated_at、has_totp、fingerprint（SSH）。

## 8. 加密与会话

### 8.1 密钥层次

1. 用户主密码  
2. Argon2id(主密码, salt, 参数) → KEK  
3. 随机 256-bit 数据密钥 DEK  
4. `wrap(KEK, DEK)` 存 SQLite  
5. 若开启 Hello：生成随机 256-bit `hello_key`，用它 wrap DEK 得到 `wrapped_dek_hello` 存 SQLite；把 `hello_key` 写入当前 Windows 用户的 Credential Manager（条目名 `Sealbox/hello_key`）。解锁时：`UserConsentVerifier` 确认本人 → 读 CM 取 `hello_key` → unwrap DEK。第一版 Hello 不绑定独立 TPM 密钥。  
6. `AES-256-GCM(DEK, nonce_i, secret_blob_i)` 存每条条目  

Windows Hello **不是**第二套 KDF。它是「已登录的 Windows 用户 + 一次本人确认」之后，从 Credential Manager 取出 `hello_key`。能操作该 Windows 账户并通过 Hello 的人，可以不输入主密码解锁。主密码仍是备份、换机、关掉 Hello 之后的唯一根。

改主密码：用旧 KEK 解 DEK，用新 KEK 再包装；Credential Manager 里的 Hello 材料同步重做。关闭 Hello：删除 CM 条目，只留主密码路径。

### 8.2 首次使用

无库文件 → 引导：设主密码（最短 10 位，有强度提示，不强制特殊字符组合）→ 可选开启 Hello → 写库。

### 8.3 解锁 / 锁定

- 解锁页：主密码；Hello 可用且已开启时显示 Hello 按钮。Hello 取消或失败则留在本页，改输主密码。
- 解锁成功：DEK 进 Rust 会话；启动空闲计时（默认 15 分钟，可在设置改）。
- 锁定触发：标题栏锁、托盘「锁定」、空闲超时、应用退出。
- 锁定动作：DEK 从内存丢掉（Rust 侧 zeroize）、取消显示明文定时器、若剪贴板仍是本应用写入的秘密则清空、界面回解锁页；快捷键小窗同样变成解锁。
- 关主窗口到托盘：不锁定。
- 进程被杀或崩溃：下次启动视为已锁定。

### 8.4 失败

主密码错误：提示「主密码不正确」，失败次数越多延迟越长（封顶约 2 秒），不销毁库。审计记失败，不记尝试内容。

## 9. 界面

视觉对齐参考截图：浅色、自定义标题栏、左侧窄图标栏、保险库内再分分类侧栏 + 表格、紫色主按钮、类型彩色胶囊、行高偏松、键名首字母色块。功能不抄截图里的试用条、AI 开关、分页、刷新额度、Bitwarden 导入。

### 9.1 窗口铬

- 无边框；左上应用图标；后退/前进 + 面包屑
- 中：解锁状态绿点 + 条数
- 右：聚焦搜索、锁定、最小化/最大化/关闭
- 关闭主窗口 → 托盘；托盘菜单：打开、锁定、退出

### 9.2 图标栏

1. 首页  
2. 保险库（默认）  
3. 审计  
4. 底部：设置 + 解锁状态点  

禁止出现第一版做不完的入口（AI、MCP、存储、文件加密、工作区、浏览器、邮件、MQTT）。

### 9.3 保险库

**分类侧栏**

- 全部凭据 + 计数
- 类型：网站账号、API Token、SSH
- 标签（没有任何标签则隐藏整块）
- 文件夹、未归类、新建文件夹
- 回收站
- 备份 / 还原

**主区**

- 搜索（Ctrl+F）：键名、账号、网址、标签、文件夹。不含备注。
- 排序：使用次数（默认）、修改时间、键名；置顶始终在前
- 「+ 新建凭据」：选类型后打开同一套表单（抽屉或对话框，全局一种）
- 表格列：勾选、键名（色块 + 可选钉）、关联账号、类型、修改时间、次数、过期、操作。勾选后顶部出现批量条：移入回收站（须确认）。不允许批量复制秘密。
- 有 TOTP 的网站行：时间列第二行显示 `TOTP`；行内可复制验证码
- 行内操作：复制主秘密、复制账号、显示一次、编辑、删除
- 空状态：一句话 + 新建按钮
- 列表本地全量，不做分页

**表单字段**

- 公共：键名、文件夹、标签、备注、过期、置顶
- 网站：网址、用户名、密码（可生成）、TOTP 密钥（可选）
- Token：服务、账号、Token
- SSH：密钥类型、私钥（可粘贴）、口令（可选）；保存时计算指纹

### 9.4 快捷键小窗

与主窗口同一套颜色和类型色标。无侧栏、无表格。未解锁则只显示解锁；已解锁则搜索列表，方向键选择，回车复制主秘密，Esc 关闭。

### 9.5 交互统一

- 危险操作（删除、清空回收站、导入覆盖）二次确认
- Toast 短、不展示秘密
- 显示明文超时收回掩码（默认 10 秒）

## 10. 把秘密用出去

### 10.1 复制

- 主秘密：网站密码 / Token / SSH 私钥
- 次操作：账号；网站还可复制 TOTP
- 写入系统剪贴板后，Rust 记下本次 payload 的哈希与截止时间（默认 20 秒，设置可改）
- 到期时：若当前剪贴板内容仍等于那次写入，则清空；用户已复制了别的东西则不动
- 复制成功增加 `use_count`，更新 `last_used_at`，写审计

### 10.2 显示

向核心要一次明文，仅在该字段展示，超时掩码。写审计「显示」，不写值。

### 10.3 密码生成

仅本机：长度、大小写、数字、符号。插入当前密码框，未保存前不入库。

### 10.4 禁止

自动填充网页、模拟键盘把秘密打进其他程序、把秘密写到临时文件、把备份默默传到网络。

## 11. 备份

- 格式：单一文件，扩展名 `.svbak`。内容为版本头 + 随机盐 + 用**主密码**经 Argon2id 派生的钥加密的库快照（条目、文件夹、标签；不含 Hello 材料、不含本机路径）。第一版不单独设备份口令。
- 导出：选路径，再输入一次主密码确认。不把 DEK 裸放进文件。
- 导入：主密码错误或文件损坏 → 本机库不动。
- 空库（尚未设密码）导入：用**导出时的主密码**解开快照，该密码成为本库主密码；Hello 默认关。
- 已有库导入：必须先解锁。对话框再要一次**备份文件的主密码**。解开快照后，每条新条目的 `secret_blob` / `notes_blob` 用**本库 DEK** 重新加密再写入。不替换本库 KEK，不改本库主密码。
- 默认策略：按 `id` 合并，已存在跳过，新 id 插入。
- 「用备份覆盖本机」为显式高级选项，二次确认。
- Hello 不能解密备份。换机：导入 + 主密码；Hello 在新机重开。
- 第一版无定时备份、无网盘。

## 12. 错误处理

| 情况 | 用户看到 | 系统 |
|---|---|---|
| 主密码错 | 主密码不正确 | 延迟递增；审计失败 |
| Hello 不可用/取消 | 仍可输主密码 | 不视为库损坏 |
| 备份口令错/文件坏 | 无法打开备份 | 本机不变 |
| 导入部分失败 | 成功/跳过/失败条数 | 已写入保留 |
| 库文件损坏打不开 | 库文件有问题，引导从备份还原 | 不自动覆盖 |
| 热键被占用 | 设置里提示，可改键 | 主窗口复制仍可用 |
| 磁盘满/无权限 | 无法保存 | 编辑不提交 |
| 剪贴板清不掉 | 不弹致命错 | 审计；下次锁定再试 |
| 崩溃 | 下次须重新解锁 | 无自动登录 |

日志与崩溃信息做脱敏：匹配常见 Token 前缀与 PEM 头则替换为 `[redacted]`。

## 13. 测试

### 13.1 Rust 单元

- Argon2 派生稳定；AES-GCM 往返；篡改密文解密失败
- 改主密码后：新密码能开库，旧密码不能；旧备份仍只用旧口令开
- DEK wrap/unwrap；zeroize 后会话拒绝解密

### 13.2 金库集成（无 UI）

- 三类 CRUD；搜索命中键名/账号/网址/标签且返回 DTO 无 blob；备注不在搜索范围内
- 已有库导入另一主密码的备份：新条目可被本库主密码解锁，备份主密码不能直接开本库
- 删除进回收站；30 天逻辑用注入时钟测物理删
- 导出 → 新库导入合并；覆盖标志才替换
- 锁定后 decrypt/copy 返回需解锁错误

### 13.3 会话

- 解锁 → 复制 → 到期后剪贴板不是原秘密（可测缩短超时）
- 超时锁定后复制失败

### 13.4 Windows 冒烟

首次设密码、Hello 开关（无生物设备则跳过）、列表搜索、行内复制、热键小窗回车复制、备份导出导入。

不测：浏览器填充、MCP、多设备同步、非 Windows。

## 14. 安全属性（实现时不可破）

1. 前端、审计、日志、备份文件（无口令时）、SQLite 文件本身，都得不到秘密明文。
2. 显示和复制是唯一把明文送到 UI/剪贴板的出口，且有超时。
3. 同一把 DEK；Hello 只是 Credential Manager + 本人确认，不是第二套库。
4. 备份只用主密码加密，与 Hello 无关；Hello 不能解开 `.svbak`。
5. 第一版不监听端口，不发网络请求（界面无更新检查也可以；若以后加更新检查不得上传金库数据）。
