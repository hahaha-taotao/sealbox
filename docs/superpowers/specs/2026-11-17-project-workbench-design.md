# Sealbox 项目工作台实施方案

- 文档版本：v1.0（建议实施基线）
- 编写日期：2026-11-17
- 适用项目：现有 Sealbox 密码管理器
- 使用定位：个人优先、本地优先；以后可向同事分发应用，多人协同另行建设
- 首版范围：本文阶段 A；B–E 是后续范围，不自动进入首版
- 核对范围：依据本地源码，不代表已完成真实平台连通、字段、权限或提交验证
- 本轮授权：只编写方案，不实施业务代码、不连接办公平台、不提交远端数据

## 1. 目标与关键决策

在现有密码管理器内新增独立“项目工作台”，复用 ZoomKey CRM、Jira 查询与凭据管理，以及现有邮件和附件能力。不另造办公平台，不复制维护平台已有主数据。

首版闭环：

> 查询 CRM 客户/项目 → 纳入我的项目 → 选择产品模板生成计划 → 调整节点、关联 Jira 任务 → 标记完成或异常 → 查看甘特图 → 到期提醒。

后续接入服务单、工作/出差日志、项目成本、邮件发票收集与申请。

已确定的方向：

1. 沿用 Vue + Tauri + Rust；个人首版不部署独立服务器。
2. 一个应用、独立业务模块。保险库负责凭据，不把项目记录塞进密码备注。
3. CRM 业务项目是关联主线；本地项目有独立 UUID，绑定平台来源和远端 ID。
4. CRM 项目与 Jira 项目不强制一一对应，支持多个 Jira 范围和精确任务关联。
5. 平台业务事实以平台为准；本地计划、模板、异常、日志草稿以本地为准。
6. 首版 CRM/Jira 只读，本地勾选完成不修改远端任务。
7. 锁定金库后隐藏业务内容，停止凭据同步和业务明文访问，不为提醒常驻保存密钥。
8. 同事各自安装不等于共享数据；不通过复制个人金库实现团队协作。

## 2. 现有能力、证据与建设缺口

### 2.1 已核实的源码基础

| 能力 | 源码证据 | 可复用内容 |
| --- | --- | --- |
| Vue/Tauri/Rust | `package.json`、`src-tauri/`、`crates/sealbox-core/` | 前端、桌面后台、共享核心 |
| CRM 只读接入 | `src-tauri/src/zoomkey/crm.rs` | 客户、项目、服务合同、成员、字段描述、查询、单条读取 |
| Jira 只读接入 | `src-tauri/src/zoomkey/jira.rs` | 项目、任务、状态、JQL 分页查询 |
| 凭据范围内平台操作 | `src-tauri/src/http_profiles.rs`、`src-tauri/src/profile_http.rs` | 认证、固定操作、参数校验、风险与执行边界 |
| 会话与锁定 | `src-tauri/src/session.rs`、`src-tauri/src/lock.rs` | 会话代次、密钥/缓存生命周期 |
| 邮件与附件 | `src/lib/tauri.ts`、`crates/sealbox-core/src/mail*.rs` | 看信、列出附件、保存附件 |
| 页面入口 | `src/App.vue` | 可接新增入口；新业务不继续集中堆入该文件 |
| 数据库与密码学 | `crates/sealbox-core/src/db.rs`、`crypto.rs` | SQLite 迁移、AES-GCM、随机密钥、密钥包装 |
| 备份 | `crates/sealbox-core/src/backup.rs` | 带版本封装、校验、恢复与目标密钥转换 |

CRM 已有字段映射涉及 Accounts、Project、Members、ServiceContracts、SalesOrder、HelpDesk、Hour，覆盖客户、项目关联、工时、出差人天等。合同额、回款字段不等于完整成本数据；HelpDesk 映射也不等于已确认真实服务单流程。

### 2.2 不能当作现成功能的事项

- 内置 ZoomKey 操作目前只读。通用 HTTP 支持写方法，不代表 CRM/Jira 的业务写入已经接通。
- `ToolOutcome` 和内置执行入口主要返回阅读用文本。页面需要结构化 DTO，不能解析文本充当稳定 API。
- `http_profiles.rs` 的内置准备流程还检查 MCP 启用。需拆分“平台连接授权”和“对外 MCP 开关”，页面不要求额外开启对外 MCP，也不能绕过 Profile/会话/目标校验。
- `db.rs` 使用普通 rusqlite/SQLite。属于密码管理器不代表整个数据库文件已加密；项目正文、关联、日期和缓存必须显式加密。
- 现有邮件缓存是可重建数据，不进备份；原创计划不能套用这个规则。
- 当前备份封装为版本 2，扩展位置为 `BackupEnvelope`。新增数据库表不会自动进入备份。
- 尚未核实有独立工作日志、项目排程、甘特图或项目提醒模块，不能把凭据备注当作完整笔记系统。

### 2.3 仍需真实环境确认

首版接平台前确认：可见模块/字段、当前账号权限、数据规模/限流、项目与任务实际映射。后续写入前确认：服务单/费用/发票所在模块、必填字段、附件、审批、幂等或提交后查询能力。

这些是相关阶段的准入条件，不阻碍本地模板、计划、排程等能力开发。

### 桌面与移动端边界

首版项目交互以桌面为主。移动端不展示项目入口、不承诺项目后台提醒；但同版本移动端打开金库、保存其他条目、备份/恢复时必须保留项目数据，因此持久化与备份放共享核心。

遵守 `AGENTS.md`：共同版本号，每次构建同时覆盖桌面和 Android；正式发布沿用 Windows/Linux/Android 统一入口，不增加单端版本或工作流。完整移动甘特图另行安排。

## 4. 页面与核心流程

### 4.1 导航

新增“项目”一级入口，与保险库、邮件并列。阶段 B 再增加工作日志入口或视图。

| 页面 | 内容 |
| --- | --- |
| 我的项目 | 项目/客户、当前阶段、下一节点、逾期/阻塞数、负责人、同步时间、归档筛选 |
| 平台查询 | 项目编号/名称、客户名称查询；客户结果展开关联项目 |
| 项目详情 | 概览、计划列表、甘特图、关联任务、活动记录；后续开放日志/服务/成本/票据 |
| 模板管理 | 创建、复制、编辑、停用、生成预览；版本与示例标识 |
| 待办/提醒 | 即将到期、逾期、受阻；区分本地节点和平台任务 |

页面必须覆盖加载、空结果、离线缓存、无权限、失败与重试。展示来源和数据时间，不把旧缓存标为刚同步成功。

### 4.2 纳入我的项目

1. 查询 CRM 客户或项目，预览项目编号、签约客户、实际使用方。
2. 点击“纳入我的项目”，仅创建本地工作区关联，不在 CRM 新建项目。
3. 选模板或空白计划，填写启动日或交付日、默认负责人。
4. 预览日期、节点、依赖和冲突，确认后保存。
5. 配置 Jira 项目/任务范围，逐条关联必要任务。

同来源账号范围、同 CRM 项目重复纳入返回已有项目。签约客户与实际使用方分角色，不合并成一个模糊的客户字段。名称相似只可提示候选，不自动绑定。

### 4.3 归档与删除

首版项目只做本地归档：保留计划/异常/关联，暂停该项目自动同步和提醒，可恢复。不删除平台项目。永久删除延后。

删除节点需预览依赖和任务关联影响，保留变更事件；有执行记录的节点优先取消而非硬删除。取消节点的依赖需明确解除或重连，不把取消等同已完成。

## 5. 模板与排程

### 5.1 模板结构

模板有稳定 ID、不可变版本、产品、说明、适用条件、工作日历和节点集合。普通节点工期为正整数工作日；里程碑为 0 天事件。节点包括标题、排序、工期、负责角色、依赖、交付物清单。

生成计划保存模板版本和节点快照。改模板不修改既有项目。真实产品模板由用户确认后录入；首版仅附“通用交付示例”，含启动、勘察、部署、调试、培训、试运行、验收，工期为可调整示例，不冒充既有产品标准。

负责角色不自动匹配真实平台人员；个人首版可默认负责人为“我”。

### 5.2 日期与日历

- 业务日期用 `YYYY-MM-DD`；工作区默认时区 Asia/Shanghai；创建/修改/同步时间为 UTC 时间戳。
- 默认周一至周五工作日，支持显式设置休息日/调休工作日。未维护例外时，不宣称已覆盖法定节假日。
- 支持启动日正排、交付日倒排，首版不同时强制两个锚点。
- 正排非工作日锚点移至下一工作日；倒排移至上一工作日，预览说明调整。
- 一个项目首版一份当前计划。重新套模板不得悄悄追加重复节点：空白/未执行计划可预览替换；有执行历史时改用节点编辑，暂不整体覆盖。

### 5.3 依赖与工期的精确定义

首版只实现零间隔“完成后开始”（FS），依赖图必须无环。普通工期按工作日从日初至日终，0 天里程碑是标记日的日终事件。

- N 天工期含开始日，1 天节点开始日等于结束日。
- 对边 P→N，N 为普通节点时：`N.start >= next_workday(P.end)`。
- N 为里程碑时：`N.date >= P.end`。所以里程碑可与前置同日，依赖它的普通任务从下一工作日开始。
- 正排取满足所有前置的最早日期；多个前置取最晚约束；无依赖普通节点可并行。
- 倒排取满足所有后继的最晚日期。N 为普通节点时：`P.end <= previous_workday(N.start)`；N 为里程碑时：`P.end <= N.date`。
- 多后继取最早约束；倒排所有终点以交付日为上界，可使用虚拟终点汇总。根里程碑正排在锚点日，终点里程碑倒排在交付日。
- 普通节点工期必须大于 0，只有里程碑可为 0；不支持负工期、循环、自依赖、跨计划引用。

### 5.4 基线、改期与冲突

保存基线开始/结束、当前计划开始/结束、实际开始/完成。首轮生成确认后建立基线，后续改期不覆盖。

用户可锁定节点日期。延期时不自动改完整计划，而是预览受影响节点与日期差异；确认后只调整未完成且未锁定节点。约束冲突明确报错，不静默移动锁定或已完成节点。

预览携带原 revision；提交时再次校验，其他窗口已修改则返回冲突，重新预览。批量改期必须事务提交，不能只保存一半。

### 5.5 固定验收例子

无节假日例外时，以 2026-11-17（周二）正排，A 2 天，B 3 天且依赖 A：

| 节点 | 开始 | 结束 |
| --- | --- | --- |
| A | 2026-11-17 | 2026-11-18 |
| B | 2026-11-19 | 2026-11-23 |

跳过 21、22 日周末。以 2026-11-23 倒排同一无余量链应得到相同结果。

在 A、B 中间增加 0 天里程碑 M，M 为 2026-11-18，B 仍于 19 日开始；倒排相同。

并行/有余量图的正倒排可能日期不同，不要求强行一致，但都必须满足同一组依赖约束。

## 6. 完成、异常、任务关联与甘特图

### 6.1 节点状态

状态为 `not_started / in_progress / completed / cancelled`。延期由未完成状态和当前计划日期计算；阻塞、客户原因、资料待补作为独立异常。

异常有类别、程度、说明、创建/解决时间、影响范围和处理记录。节点完成后可仍有资料待补异常。

完成需保存实际完成日；重新打开保留历史。重要里程碑若缺交付物或存在阻断异常，明确提示并人工确认，不因任务全部完成自动验收。

首版进度为“节点完成率”：已完成有效节点数/全部有效节点数，取消节点不计分母，里程碑计一个节点。无有效节点显示“未建立计划”而非 100%。不冒充工期完成率。

### 6.2 Jira 关联

节点与 Jira 任务多对多，保存来源、稳定 issue ID、可变 key、最近状态与同步时间。一个 CRM 业务项目可关联多个 Jira 项目，也可只关联其中部分任务。

首版本地完成不写 Jira。任务全完成只提示“可确认节点完成”；无权限、删除、不可见的任务保留关联并标明状态，不当作已完成。

完成判定优先使用状态类别/平台元数据，允许项目级确认映射。未知状态提示待确认，不能把现有工具的 Done/Closed 预设当所有项目的通用规则。

### 6.3 甘特图

列表与甘特图读同一份计划。首版支持周/月尺度、今天线、节点条、里程碑、延期/异常提示、点击详情；不做拖拽改期、资源均衡、关键路径或复杂依赖类型。

可先用 SVG 实现，避免首版引入重型依赖。新增第三方库先核对许可、离线打包、Vue 兼容，不使用上传业务数据的云端图表服务。

## 7. 同步、离线与提醒

### 7.1 平台数据同步

- 用户显式绑定 CRM/Jira 凭据，业务数据只保存引用，不保存密码、令牌、认证会话或私钥。
- 解锁且联网时手动刷新；可开启每 15 分钟同步“我的项目及关联任务”，不全量扫描平台。
- 完整遍历分页，按远端 ID 去重；中途失败标记部分成功，不把未获取记录当成删除。
- 查询可逐条更新缓存，但只有完整范围拉取成功才更新该范围的完整成功时间。
- 平台跨页变化时采用稳定排序并记录同步时间区间；无快照接口时不宣称事务一致，缺失记录不能凭单轮查询自动删除。
- 离线可编辑本地计划、查看解锁缓存；显示缓存时间。远端刷新不覆盖本地原创计划。
- 401/403 停止重试提示认证/权限；429 尊重 Retry-After；临时网络/5xx 限次退避，每轮最多 3 次自动重试。同来源刷新合并，不并发全量拉取。
- 锁定停止新请求；尽可能取消在途请求并丢弃晚到结果。提交前复核会话代次、来源 revision、凭据/Profile 有效性，旧会话/旧授权结果不入库不展示。
- 不长时间持有全局会话锁进行网络请求；受控的短期认证副本在请求结束/取消后销毁，不持久化。
- 同站点换账号不复用旧账号缓存；凭据失效/缺失标记待绑定，保留原创计划，不自动换绑同名账号。

### 7.2 提醒规则

默认：截止前 1 个自然日 09:00、截止日 09:00；已逾期节点每天 09:00 最多一次。以工作区时区计算，截止日结束仍未完成，下一自然日起算逾期。支持关闭和调整规则。

首版仅本地节点产生系统通知，不为关联 Jira 任务重复发一份。完成/取消节点或归档项目后取消后续通知；取消归档或重开节点重新计算。

去重键包含节点、规则、`reminder_revision`、触发时刻。此版本只在截止日、规则、重开等影响提醒的变更时递增；改标题、异常备注不递增。改期撤销旧提醒后重建。

稍后提醒默认 1 小时，节点完成/改期取消旧稍后提醒。新建/改期时已过的提前提醒不逐条补发，进入当前状态摘要。

队列与通知记录持久化，正常重启不重复已发事项。恢复/解锁补报合并摘要，不逐条轰炸。系统通知无事务回执时不承诺崩溃下恰好一次，采用稳定通知 ID 降低重复。

### 7.3 运行与权限边界

只在应用运行/托盘且金库解锁时发送项目通知。锁定不显示客户、项目、正文，解锁后补报；退出、休眠、关机不保证准点通知，不为此延长金库解锁。

通知权限被拒时保留应用内提醒并显示系统通知不可用。锁定时清空页面业务状态并尽可能撤下本应用已发送的业务通知；操作系统已有通知历史无法保证彻底回收，因此通知正文默认使用通用摘要，不含客户名/敏感正文，点击解锁后查看。

## 8. 后续业务设计

### 8.1 日志、出差、服务单

一次录入项目、日期、地点、服务内容、结果、遗留问题、附件，可分别整理工作日志、出差日志、服务单草稿，通过引用复用，不互相覆盖。

出差含起止日期、目的地、关联项目、每日记录、费用。一趟多个项目需明确分配，不推断费用比例。自由笔记可关联工作日志，但不在首版造完整知识库。

服务单先做草稿。确认真实模块、字段、附件、审批、写权限后，再开发预览提交；保存远端 ID/回执，平台失败不显示成功。

后续统一提交状态：`draft → pending_confirmation → submitting → succeeded / failed / outcome_unknown`。保存本地请求 ID、内容散列、远端 ID；支持幂等键则使用。超时可能已成功时先核对，不自动重发。内容变化后旧确认失效。

业务提交需显式预览确认，不能因通用层存在会话授权而省略。自动摘要保留原始记录和来源，人工确认；默认不把业务数据发往外部服务，不把任务更新编成“已完成现场交付”。

### 8.2 成本

分开显示预算、已发生费用、报销流转、付款状态，不能把四种口径直接相加。费用以原始业务 ID 去重，报销/付款记录作为关联状态补充。

工时/出差人天不是金额。人工费需明确费率、有效期、权限和规则，估算单列；每笔金额保存币种及税口径，不同币种不直接相加。分摊比例明确且合计 100%，使用定点金额而非浮点累计，舍入差额显式处理。

合同额、应收、回款不是成本。来源缺失明确展示，不宣称完整成本、利润或财务对账准确。每个汇总可追溯到源单据与同步时间。

### 8.3 邮件发票与申请

指定邮箱/文件夹 → 收集疑似发票附件 → 保存加密原件与来源 → 识别校对 → 去重 → 确认项目/类别/分摊 → 草稿 → 确认提交。

文件散列识别完全重复附件；业务去重结合类型、号码、开票日期、开票方等并人工复核，不把散列不同当不同发票。更正、红字、作废发票单独关联。

识别显示置信度与原件，不等于查验真伪。来源至少保存账号引用、文件夹、UIDVALIDITY（接口可取得时）、邮件 UID、附件标识/散列。源邮件删除不应导致已保存原件丢失。

压缩包、外部链接、超大附件单独限制；不自动执行附件、打开陌生链接或静默解压不受信内容。具体申请平台/模块未确认，不预先承诺可提交。

### 9.2 结构化适配

把“查询并取得结构化结果”和“工具阅读文本格式化”分开。现有工具维持安全边界和文本兼容，页面使用 DTO；不正则解析 ToolOutcome.text，不建第二套密码管理。

分页结果包含 `items / next_cursor / complete / fetched_at / source_binding_id / warnings`。错误区分 locked、source_unavailable、permission_denied、validation、conflict、rate_limited、network、remote_error；日志不含认证信息、完整敏感查询或正文。

提供具名的客户/项目查询、项目详情、任务搜索和状态元数据；页面不开放任意 SQL/JQL 输入。关键词转义/绑定，不能借参数覆盖请求目标/方法/认证。

拆出页面与 MCP 可复用的准备/复核方法：平台连接授权独立于对外 MCP 开关；MCP 自己仍保留开启和认证要求。禁止临时开启 MCP 或跳过 Profile 来访问平台。

### 9.4 存储与密钥

首版采用**同一金库 SQLite 内独立项目表、业务 payload 逐条加密**，不另维护第二个数据库，也不把项目塞入 entries 条目类型。

建议物理结构：

- `pm_workspaces`：随机工作区 ID、格式版本、包装后的业务密钥。
- `pm_records`：随机记录 ID、工作区 ID、实体类型、schema_version、revision、加密 payload；主键范围包含工作区。
- 模块迁移版本独立管理；所有变更事务化、幂等化。

项目名、客户、来源账号/关联 ID、日期、描述、预算、缓存、通知正文、业务时间和删除状态放入加密 payload。不建明文全文索引；必要的随机标识、类型、技术版本为明文，因此不宣称记录数量/类型保密。

每工作区生成随机 256 位业务密钥，由现有 DEK 加密包装，包装内容绑定模块、工作区、版本。业务记录用 AES-GCM，认证附加数据 AAD 绑定工作区/记录 ID、实体类型、schema、revision。

当前 `crypto.rs` 的 encrypt/decrypt 没有 AAD 参数，需新增兼容 helper，不能假设已支持；不改旧密文格式，不破坏凭据解密。密钥只在解锁会话中使用，锁定销毁，禁止写普通配置/日志。

搜索首版在解锁后内存过滤，锁定清空；不把明文索引写 localStorage、临时数据库、普通日志、未加密 WAL。明文短时进入页面内存，不对操作系统内存/交换文件作绝对保密承诺。

所有写入经同一事务服务做业务唯一性与预期 revision 校验；冲突返回 conflict，不能后写覆盖。缓存可丢弃，模板/计划/异常/日志/关联不可当缓存清理。

### 9.5 备份、恢复、现有同步

1. 将 `BackupEnvelope` 扩至版本 3，带可选 projects 扩展和独立 schema；同步更新版本校验、inspect、export、restore_new、restore_into 和移动共享调用。
2. 新客户端兼容 v1/v2。缺项目扩展表示源备份没有项目，不隐式清空目标已有项目。旧客户端不承诺读 v3，导出/升级提示版本要求，不建议降级操作含项目数据的金库。
3. 备份包含模板版本、计划/基线、节点、异常、活动、关联、提醒规则、归档、墓碑。排除平台缓存、临时分页、待投递作业；恢复后重算提醒，不逐条重放过期通知。
4. 工作区密钥与记录封装于现有密码保护备份。校验全部密文和引用；恢复到新金库时把工作区密钥重新包装到目标 DEK，不能直接沿用源 DEK。
5. 恢复已有金库先预检：同工作区提供跳过/整工作区替换及影响预览，不做隐式字段合并；不同工作区可新增。凭据与项目同时恢复时同事务提交，失败回滚。
6. 凭据缺失/被跳过/身份不一致时标待重绑，不自动选同名账号。恢复不立即联网，解锁确认来源后再同步。
7. 项目不加入也用于既有同步的 `BackupSnapshot`，不受现有凭据同步墓碑影响。首版凭据同步不包含项目，界面须说明；项目使用本地加密备份。
8. 阶段 A 不接收项目二进制附件，交付物先是清单/说明/平台链接。B/D 上线附件前补齐加密对象存储、大小限制、完整备份和引用校验，不能只备份绝对路径。当前备份有 128 MiB 上限，附件阶段不得静默遗漏或越限。

## 12. 以后共享给同事

区分三个层次：

1. 各自安装、各自用自己的数据：不需要协同服务器。
2. 分享项目快照：明确选择字段、获准接收者，提供脱敏和导出预览。
3. 多人共同编辑：另建团队身份、项目权限、同步服务、冲突/离线策略、审计与部署。

当前仅为未来保留 workspace_id、来源身份、revision、墓碑、事件历史，不建设团队账号或假称已支持同步。

共享不能连同个人金库、密钥、无关邮件打包；平台缓存/成本是否可共享须确认公司授权与接收者权限。未来不能用某个人的平台凭据替其他人绕过平台权限。

| 附件 | A 仅清单/说明/平台链接 | 加密对象、备份限额、完整性恢复 |
| 协同 | 同事可独立使用，暂不共享 | 身份/权限、同步方式、公司数据政策 |

实施从 A1 开始。若具体接口不可用，只暂停相关平台能力，不以待确认事项无限阻塞本地基础功能；不能用网页自动化绕过权限来兑现未经验证的接口承诺。更换接入方式需另行授权与评估。
