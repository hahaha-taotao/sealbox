## 目标
修复金库页面表格的两个 UI 问题：
1. 操作列在横向滚动时，表体操作按钮仍随内容移动，不能稳定冻结在右侧。
2. “关联账号”列被长账号/指纹自动撑宽，挤压其他列；改为固定的适中宽度并截断超长内容。

## 实施步骤
1. **限定金库表样式范围**
   - 在 `src/App.vue` 的金库主表上增加明确的 `vault-table` 类名，并给“关联账号”和“操作”表头增加语义类名。
   - 保持审计表、首页概览表使用现有通用样式，避免新的冻结列规则误伤其他表格。

2. **修复操作列冻结结构**
   - 将现有 `<td class="row-actions">` 内的按钮包进一个 `.row-actions-inner` 容器。
   - 让 `td.row-actions` 保持普通 table-cell，不再直接使用 `display: flex`；将 `display:flex`、按钮间距和 `white-space:nowrap` 移到内部容器。
   - 将 sticky 规则限定为 `.vault-table` 的操作表头/单元格，并保留背景、阴影、层级和 hover 背景，确保表体单元格在表格横向滚动时覆盖滚动内容并固定在右侧。
   - 让金库表使用适合 sticky 单元格的独立边框布局（零间距），避免折叠边框造成遮挡/绘制不稳定。

3. **固定“关联账号”列宽且避免挤压**
   - 给账号单元格增加内部文本容器，设置约 `220px` 的固定可视宽度、`overflow:hidden`、`text-overflow:ellipsis` 和单行不换行；通过 `title` 保留查看完整值的能力。
   - 给金库表设置合理的 `min-width`（约 1000px，具体按现有操作按钮的最小占用取值），并保留 `min-width:100%` 的桌面适配，使窄窗口出现表格自己的横向滚动，而不是压缩键名、类型、时间等列。
   - 账号列只限制自身显示区域，证书信息/显示密码等附加内容继续保留在该单元格中并允许按现有规则换行。

4. **验证**
   - 运行 `npm run build`，确认 Vue/TypeScript/CSS 构建通过。
   - 检查变更范围只涉及 `src/App.vue` 与 `src/styles.css`，确认未修改后端数据结构或账号字段逻辑。
   - 重点验证：窄窗口横向滚动时操作按钮仍贴右侧；滚动到底部时每一行操作列与表头对齐；长账号显示省略号且其他列保持可读宽度；审计表最后一列不再被新的操作列冻结规则影响。
