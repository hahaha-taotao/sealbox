## 结论与范围

当前工作树已经有一部分 `ClientCert` 雏形（`EntryKind::ClientCert`、`SecretPayload::ClientCert`、前端表单、备份测试和 ZoomKey 消费者），但它还不是一个安全闭环：私钥仍会被通用 `reveal_secret`/`copy_secret`/编辑表单拿到，证书内容没有格式与大小校验，回收站条目仍可通过普通明文命令读取，锁定时 TLS/CRM 缓存也没有清理。

本次开发按当前最新设计文档执行：

- 客户端证书是金库内的一等条目，证书和私钥进入现有 `secret_blob`，随 DEK 加密、备份和恢复。
- CA bundle 继续作为 ZoomKey 的外部公开文件路径，不进入证书条目。
- 第一阶段先把“证书存储”做成独立、可测试、不会误泄露私钥的能力；ZoomKey 只作为后续消费者接入，不把未完成的证书能力直接暴露给 MCP。
- 不新建附件表，不保存用户机器上的原始路径，不把私钥复制到剪贴板，也不在第一阶段提供私钥导出。

仓库当前有大量未提交改动和未跟踪的 ZoomKey/助手文件。实施时会保留这些已有改动，先基于当前工作树做差异核对，只修改证书功能及其直接依赖，不重置、覆盖或清理用户现有工作。

## 领域模型决定

1. `ClientCert` 继续使用现有 `secret_blob`，避免 SQLite schema 迁移；`kind` 仍保存为 `client_cert`。
2. v1 接受 PEM 客户端证书链和 PEM 私钥；证书字段可以包含叶子证书及链，私钥必须能被 `rustls-pemfile` 解析。保留现有 `passphrase` 字段以兼容当前工作树，但当前 mTLS 消费者对带口令私钥明确拒绝，直到实现解密支持。
3. 每个 `ClientCert` 只生成公开元数据：证书 DER 的 SHA-256 指纹、证书数量和校验状态；私钥、口令、原始 PEM 不进入 `EntryDto`、列表、审计、日志、MCP 或助手结果。
4. `fingerprint` 复用现有公共列表示证书指纹；不新增明文私钥/证书内容列。
5. `kind` 与 `SecretPayload` 必须一一匹配；未知条目类型必须报错，不能静默回退成网站账号。
6. 所有明文读取（显示、编辑、复制、备注）都只针对活动条目；回收站条目必须统一返回 `NotFound`/拒绝。

## 实施步骤

### 1. 先收敛证书核心模型和校验

目标文件：

- `src-tauri/src/vault.rs`
- 新增 `src-tauri/src/certificate.rs`（或等价的证书专用模块）
- `src-tauri/src/lib.rs`
- `src-tauri/src/redact.rs`

工作内容：

- 把 `ClientCert` 的 PEM 解析、大小上限、必填字段、私钥类型和证书数量检查集中到证书模块，避免把校验散在命令和前端。
- 设定明确的输入上限，证书链、私钥、口令和总 payload 分别限长；文件导入采用带上限读取，拒绝超大文件、空文件和畸形 PEM。
- 校验证书至少有一个 `CERTIFICATE`，私钥至少有一个可解析的 private key；证书/私钥不匹配时拒绝保存。
- 规范换行和去除无意义外围空白，但不改变证书/私钥内容语义。
- 在 `Vault::upsert_entry` 前做 `EntryKind`/payload 一致性检查；为证书计算公开指纹并写入 DTO 对应字段。
- 修复列表和 DTO 解析时对未知 kind 的静默 Website 回退。
- 将 ClientCert 加入脱敏规则，覆盖完整 PEM 私钥、证书块以及 passphrase，且不能让测试/审计 detail 把这些内容写出来。
- 保持现有备份结构兼容；ClientCert 仍作为加密 JSON payload，不增加数据库表。

### 2. 建立“文件导入，不把私钥送进 Vue”的 Tauri API

目标文件：

- `src-tauri/src/commands.rs`
- `src-tauri/src/lib.rs`
- `src/lib/tauri.ts`

工作内容：

- 新增专用的客户端证书创建/更新命令：接收用户通过文件选择器选出的证书路径、私钥路径、公共元数据、标签/文件夹/备注和可选口令；Rust 侧读取、限长、解析、校验后直接写入金库。
- 不保存原始路径，不把文件内容通过通用 IPC 往返；路径只作为一次性导入参数使用。
- 新增只返回公开信息的 `client_cert_info` 查询，用于显示指纹、证书数量、校验状态等；`reveal_secret` 对 ClientCert 拒绝返回完整 payload。
- `copy_secret` 对 ClientCert 拒绝默认主秘密复制；如需要公开证书复制，提供单独、明确命名的“复制公钥证书”能力，绝不复制私钥或口令。
- `get_notes`、显示、编辑和其他明文命令切换到 active-only 读取。
- 新增错误信息区分：格式错误、超限、证书/私钥不匹配、带口令私钥暂不支持、条目不存在/已在回收站。

### 3. 重做证书编辑交互，移除通用私钥回显

目标文件：

- `src/App.vue`
- `src/lib/tauri.ts`
- `src/styles.css`
- `src/QuickSearch.vue`

工作内容：

- 保留“客户端证书”类型、筛选、计数、备份入口和列表展示，但将证书编辑改成文件选择导入：证书 PEM 与私钥 PEM 使用 Tauri dialog 选择路径，前端只保存路径和公开校验结果。
- 新建/编辑 ClientCert 时不再走 `openEdit -> reveal` 的通用流程；打开已有条目只读取公开信息，替换证书/私钥时重新选择文件。
- 表格行操作不再使用“复制密码”这一泛称；ClientCert 改成“查看证书信息/复制公开证书”，不提供“显示私钥”。
- `QuickSearch` 排除 ClientCert 的“回车复制主秘密”路径，防止快捷搜索意外把私钥放入剪贴板；普通凭据行为保持不变。
- 添加证书专用状态：导入中、校验失败、当前指纹、证书数量和“不保存路径”的提示；保证锁定事件清空所有公开信息/表单草稿。
- 增加 `client_cert` 的类型颜色、标签和响应式表单样式。
- 对已有工作树中直接粘贴 PEM 的旧条目保持可读取/可备份；编辑时引导重新导入，不再把旧私钥回显到 WebView。

### 4. 让锁定真正清掉证书运行时缓存

目标文件：

- `src-tauri/src/lock.rs`
- `src-tauri/src/session.rs`
- `src-tauri/src/zoomkey/tls.rs`
- `src-tauri/src/zoomkey/crm.rs`
- `src-tauri/src/zoomkey/mod.rs`

工作内容：

- 为 TLS `ClientConfig` 缓存和 CRM session 缓存增加显式清理函数，并在 `on_session_locked`、空闲锁、托盘锁、panic 清理路径统一调用。
- 不让包含私钥的 `Arc<ClientConfig>` 或包含会话凭据的缓存跨越金库锁定周期。
- `Session::set_unlocked` 在替换已有会话前先清理旧 DEK，避免旧密钥未清零。
- ZoomKey 运行时仅使用活动 ClientCert；证书被移入回收站、删除或锁定后，旧缓存不能继续请求。
- 修正 ZoomKey `tools/list` 的暴露条件：除端点开关外，还需满足内网开关、活动凭据、活动证书和 CA 配置；未配置的能力不应伪装成可用工具。实际调用仍需再次校验。
- 对带口令私钥明确返回可操作错误，不把口令或私钥内容写入审计/错误日志。

### 6. 测试与验收

Rust 测试：

- `ClientCert` CRUD、列表 DTO 不泄露 PEM/私钥、指纹稳定。
- PEM 解析、空输入、畸形输入、超限、证书链、私钥类型和证书/私钥不匹配。

- ClientCert 不走通用复制/回显；回收站条目不能通过 reveal/copy/notes 读取。

- 锁定、空闲锁、panic 清理会释放 DEK、TLS ClientConfig 和 CRM session cache。
- ZoomKey 工具暴露门禁、活动证书选择、CA 路径和缓存失效。

- 所有失败测试和现有工作树中的预存失败会如实记录，不用“跳过”掩盖。

## 第一阶段交付标准

完成后应满足：

1. 用户可以在保险库中新建、编辑、筛选、备份和恢复客户端证书条目。
2. 证书/私钥只在 Rust 内读取和加密，列表、搜索、审计、MCP、助手和 QuickSearch 不会意外返回或复制私钥。
3. 锁定后 DEK、证书运行时缓存和前端明文状态都被清掉。
4. ClientCert 可以作为后续 ZoomKey mTLS 的唯一证书来源，但 ZoomKey 不会在证书功能未配置完整时暴露“看似可用”的工具。
5. Rust 单元/集成测试、前端类型检查与构建全部通过，或明确列出与本次无关的既有失败。

实施顺序会先完成证书核心和安全边界，再接前端导入，再接锁定/ZoomKey 消费者，最后跑完整测试与更新文档；不会先扩大 MCP 暴露面再补存储安全。
