## 目标
在主窗口左侧导航的“插件”下方增加一个名为“助手”的页面，提供：

- 基础多轮 AI 对话；
- OpenAI Chat Completions 兼容接口配置（模型、Base URL、API Key）；
- 通过真实的本机 HTTP MCP 接口执行 `initialize`、`tools/list` 和 `tools/call`，用于验证 MCP 与工具连通性；
- 将当前 MCP 暴露的只读工具交给模型自动调用，并在界面展示工具调用轨迹。

首版明确不做流式输出、外部 MCP Server 列表、stdio/SSE transport，也不暴露 `copy_secret`、`http_request` 等高风险工具。助手默认连接 Sealbox 自己当前运行的 `127.0.0.1` MCP 服务，走实际 HTTP/JSON-RPC 路径而不是直接调用内部函数。

## 后端实现

### 1. 新增助手模块
新增 `src-tauri/src/assistant.rs`，集中实现：

- 助手配置读取与校验；
- OpenAI 兼容请求/响应解析；
- MCP HTTP 客户端；
- 工具调用循环；
- 不含 Tauri 状态细节的纯函数与单元测试。

配置分两类保存：

- `assistant_model`、`assistant_base_url` 使用普通 Vault settings；
- `assistant_api_key` 使用 `set_secret_setting` 加密保存；
- 对前端只返回模型、Base URL 和 `has_api_key`，绝不返回 API Key。

默认 Base URL 使用 `https://api.openai.com/v1`，默认模型使用常见的 OpenAI 兼容模型名；用户可改为其他兼容服务或本机模型端点。API Key 允许为空，以兼容本地模型。

### 2. 新增 Tauri 命令
在 `src-tauri/src/commands.rs` 增加 DTO 和 command bridge，并在 `src-tauri/src/lib.rs` 注册：

- `assistant_config_get`：读取非敏感配置视图；
- `assistant_config_set`：保存模型、Base URL 和可选 API Key；
- `assistant_mcp_probe`：确保当前 MCP 启动，通过真实 HTTP JSON-RPC 完成初始化和工具发现，返回连接状态、地址和工具摘要；
- `assistant_chat`：接收当前对话历史、用户消息和是否启用工具，返回最终文本以及工具调用轨迹。

`assistant_chat` 的工作流：

1. 要求金库已解锁，并执行空闲锁定检查；
2. 确保当前 MCP Server 已运行，后端从 `McpState` 读取 Token，不把 Token传给前端；
3. 通过 MCP HTTP 调用 `initialize` 与 `tools/list`；
4. 仅筛选 `readOnly=true` 的工具，转换为 OpenAI `tools.function` schema；
5. 调用兼容 Chat Completions 的模型；
6. 若模型返回 `tool_calls`，校验工具名来自刚发现的只读工具目录，通过真实 MCP HTTP 调用 `tools/call`；
7. 将工具结果作为 `tool` 消息回传模型，最多循环 6 轮；
8. 返回最终回答及每次工具调用的名称、成功/失败和截断后的结果预览。

工具结果会在系统提示中明确标记为不可信外部内容，不能改变助手权限或配置。所有网络请求使用有限超时、禁止重定向、响应大小上限和输入长度限制；错误消息不回显 API Key、Bearer Token 或其他秘密。

### 3. 锁定与秘密生命周期
- 助手 API Key 永远只在 Rust 后端读取和使用；
- MCP Token 只在 Rust 后端从现有 `McpState` 读取；
- 不允许助手读取 `SecretPayload`、复制秘密或调用 legacy 高风险工具；
- 在 `App.vue` 的锁定清理路径中清空助手聊天记录、输入框、工具列表和连接状态；
- 不新增任何日志记录 API Key、MCP Token 或完整模型请求头的路径。

## 前端实现

### 1. 导航与页面
修改 `src/App.vue`：

- `Page` 联合类型增加 `assistant`；
- 面包屑增加“助手”；
- 在现有“插件” rail 按钮之后、设置按钮之前插入“助手”入口和内联 SVG 图标；
- 新增 `openAssistant()`、刷新配置/探测 MCP/发送消息等状态与方法；
- 在插件页面之后、审计页面之前增加 `v-else-if="page === 'assistant'"` 页面，避免被最后的设置页 fallback 捕获。

助手页面采用与 MCP/插件一致的卡片式布局，但视觉上偏“诊断工作台”：

- 顶部显示助手标题、模型配置状态和 MCP 连接状态；
- 配置卡：Base URL、模型、API Key（密码输入，只显示是否已配置）、保存/清除；
- MCP 卡：当前 MCP URL、测试连接按钮、只读工具数量和工具列表；
- 对话卡：用户/助手消息、工具调用状态、可展开的结果预览、输入框、发送/清空按钮；
- 忙状态禁用重复发送，错误使用现有 toast/error 样式。

### 2. 前端 Tauri 类型封装
修改 `src/lib/tauri.ts`，增加：

- `AssistantConfigView`、`AssistantConfigInput`；
- `AssistantMcpStatus`、`AssistantToolSummary`；
- `AssistantMessage`、`AssistantToolTrace`、`AssistantChatResponse`；
- 对应的 `api.assistantConfigGet/Set`、`api.assistantMcpProbe`、`api.assistantChat` 封装。

前端只维护 `has_api_key`，不缓存或展示实际 API Key；保存时才把输入值交给一次 Tauri command。

### 3. 样式
修改 `src/styles.css`，增加助手专用布局类：

- `.assistant-page`、`.assistant-layout`、`.assistant-card`；
- `.assistant-messages`、`.assistant-message.user/.assistant`；
- `.assistant-tool-trace`、`.assistant-composer`；
- 响应式布局，在窄窗口下改为单列。

继续复用现有 `--bg`、`--surface`、`--line`、`--brand`、`.mcp-card`、`.btn`、`.crumb`、`.tool-risk` 等设计变量和组件风格，不引入新 UI 依赖。

## 测试与验证

### Rust 单元测试
在 `assistant.rs` 覆盖：

- Base URL 规范化与非法 URL 拒绝；
- API 响应缺少 choices/message 时安全报错；
- tool call 参数不是合法 JSON 时不会 panic；
- 只读工具筛选会排除 `copy_secret`、`http_request` 和未标记的高风险工具；
- 工具结果和错误截断在 UTF-8 边界安全；
- 对话历史数量/单条消息长度限制；
- 锁定状态不允许助手请求。

### 现有验证命令
实现后依次执行：

```bash
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
node --test extension/fill-logic.test.js
```

然后进行一次 Windows Tauri 手工冒烟：解锁金库 → 打开“助手” → 保存兼容模型配置 → 点击“测试 MCP”确认能读到工具 → 发送一条普通消息 → 发送会触发只读 GitHub 工具的消息，确认工具轨迹和最终回答都能显示。若未配置模型/API Key，页面应仍能完成 MCP 探测并明确提示缺少模型配置，而不是崩溃。
