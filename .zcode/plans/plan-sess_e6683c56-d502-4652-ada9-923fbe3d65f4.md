## 目标
把文件夹和标签从“只能创建/列出”补成可维护的组织模型，并清理现有孤儿关系：支持重命名、删除、显式合并，且不删除凭据秘密。

## 业务语义（实现前固定）
- 文件夹重命名：保留 folder ID，所有条目关联不变；名称为空或与其他文件夹冲突时拒绝。
- 文件夹删除：删除文件夹实体，并把其下的所有条目（包括回收站中的条目）改为未归类；不删除条目、不改变秘密；删除当前筛选文件夹后刷新并回到可用列表。
- 文件夹合并：将来源文件夹下的所有条目重挂到目标文件夹，删除来源文件夹；来源和目标必须不同且都存在。
- 标签重命名：保留 tag ID 和所有 entry_tags 关联；名称为空或目标名称已存在时拒绝。需要合并时使用单独的“合并”操作，避免重命名误合并。
- 标签删除：删除标签及其所有 entry_tags 关联，不删除条目；孤儿标签不再出现在列表。
- 标签合并：把来源标签的关联转移到目标标签，依靠 `(entry_id, tag_id)` 主键去重，删除来源标签。
- 所有组织操作使用事务并写入不含秘密的审计事件；失败整体回滚。

## 实施步骤
1. **补齐 Vault 领域层**（`src-tauri/src/vault.rs`）
   - 增加组织相关错误（名称为空、目标冲突、实体不存在、来源/目标相同等），统一对文件夹和标签名称做 `trim` 校验。
   - 为文件夹增加 `rename_folder`、`delete_folder`、`merge_folders`；创建文件夹也改为使用规范化名称并拒绝重复名称。
   - 为标签增加 `rename_tag`、`delete_tag`、`merge_tags`；保留现有“保存条目时自动创建标签”，但 `ensure_tag` 改为跳过空白输入并使用规范化名称。
   - 在 `upsert_entry` 和客户端证书元数据更新中验证 `folder_id` 存在，阻止继续产生悬挂 folder_id。
   - 修改 `list_tags` 只返回仍被 `entry_tags` 引用的标签；清空/清理回收站时先清理关联关系和孤儿标签，避免历史脏数据继续污染侧栏。空文件夹不自动隐藏，交给用户显式删除或合并。
   - 复用当前单层文件夹模型，不引入 parent_id 层级或数据库破坏性迁移。

2. **补齐 Tauri 命令和前端 API**
   - 在 `src-tauri/src/commands.rs` 增加文件夹改名/删除/合并、标签改名/删除/合并命令，统一沿用 `require_unlocked` 和现有错误映射。
   - 在 `src-tauri/src/lib.rs` 注册新命令。
   - 在 `src/lib/tauri.ts` 暴露对应方法；保留现有 `FolderDto` 和标签字符串接口，避免无必要地改动备份格式和条目 DTO。

3. **增加组织管理 UI**（`src/App.vue`、`src/styles.css`）
   - 在侧栏的“标签”和“文件夹”标题旁增加“管理”入口，不改变现有点击条目进行筛选的行为。
   - 新增一个管理对话框，分别列出文件夹和标签：可编辑名称并保存，可选择目标后合并，可删除。
   - 删除和合并均显示二次确认，明确说明条目会被移到未归类或标签关联会被解除；重命名冲突和后端校验错误通过现有 toast 展示。
   - 每次成功操作刷新条目、计数、文件夹、标签和状态；保留当前未提交的配对码/扩展目录改动，不覆盖与本任务无关的工作树修改。

4. **补充回归测试**
   - 在 `src-tauri/tests/vault_test.rs` 增加：文件夹重命名保留 ID 和关联、删除后条目变未归类、文件夹合并、重复/空名称拒绝、非法 folder_id 拒绝。
   - 增加标签重命名保留关联、删除解除关联、合并去重、冲突拒绝、空标签不产生记录、`list_tags` 不返回孤儿标签的测试。
   - 增加回收站物理清理后 `entry_tags`/孤儿 tags 不残留的测试，并覆盖事务失败不留下半成品的路径。
   - 保留现有备份按文件夹名映射行为，并补一个带 tags 的 round-trip/合并测试，确保新管理操作不破坏备份导入。

5. **验证**
   - 运行 Rust 格式化、相关测试和完整 `cargo test`。
   - 运行前端 `npm run build` 做 TypeScript/Vue 类型检查和打包验证。
   - 最后检查 diff，确认只包含本任务改动加上原有未提交改动的共存，不提交或覆盖用户已有工作。
