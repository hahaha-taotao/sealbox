## 第四轮：修「新建凭据 → 客户端证书 → 选择证书，窗口就没了」

根因（已定位，不是猜测）：`App.vue` 的 `hideVisibleSecrets()` 里调了 `closeForm()`：

```ts
function hideVisibleSecrets() { hideSecret(); closeForm(); hideBridgeTokens(); }
```

它是 9-16 那次安全加固（commit 6b5ef99）加的，挂在两处失焦回调上：
`getCurrentWindow().onFocusChanged(e => { if (!e.payload) hideVisibleSecrets(); })` 和
`document.visibilitychange`。而系统文件选择框（tauri-plugin-dialog 的 `open()`）是
**应用窗口的子窗口，弹出时窗口必然失焦** → `closeForm()` → 新建凭据表单连同已选路径一起消失。

为什么只有客户端证书这条线炸、备份/还原的「浏览」没事：`hideVisibleSecrets()` 只关
`showForm`，不动 `backupOpen`，所以备份弹窗失焦后还留着。

修法（保持安全语义，只放过文件框这一段）：加 `nativeDialogDepth` 计数器 +
关闭后 400ms 宽限期，`withNativeDialog()` 包住 `open()` / `save()`；`hideVisibleSecrets()`
里改成 `if (!nativeDialogInFlight()) closeForm();`。已显示的密码、桥 token 照旧立刻隐藏。
`pickClientCertFile` / `pickBackupFile` 顺手加了 try/catch + toast，选择框打不开时不再静默。

验证：`npm run build`（vue-tsc + vite）通过。

诊断手法（下次遇到「桌面端点了某按钮窗口就没了」可复用）：

- 金库审计表能反推用户动作时间线 —— 但**必须连 `vault.db-wal` / `-shm` 一起拷**，只拷主库会漏掉最近写入
- `EnumWindows` + `IsWindowVisible`（python ctypes）能客观判断窗口是真隐藏、还是只是弹窗没了
- `GetProcessTimes` 拿进程启动时间，能判断用户有没有重启过应用
- 排查期间用户 commit 了，`git diff` 会变空；用 `git log --oneline -5` 重新对表

副作用观察（未改，待用户决定）：失焦关表单不只影响文件框 —— 点托盘图标、切到别的程序、
点任务栏都会把填了一半的新建/编辑表单丢掉。要收窄的话只保留 `hideSecret()` 即可。

## 修：测试连接 CRM 报 `Network Error: Unexpected EOF`

现象：UI 点「测试连接 CRM」→ `CRM 网络请求失败: https://crm.zoomkey.com.cn/webservice.php: Network Error: Unexpected EOF`。
注意 URL **不带 query**，说明失败的是 `login` 那个 POST，不是前面的 `getchallenge` GET。

### 定位过程（可复用的排查套路）

1. 这条文案来自 `crm.rs` 的 `ureq::Error::Transport` 分支；`Network Error` 是 ureq `ErrorKind::Io` 的 Display。
2. 在 cargo registry 里 grep 依赖源码找精确串：`Unexpected EOF` 只出自 `ureq-2.12.1/src/response.rs:782`
   的 `read_next_line`（`Ok(0)` → 连接已断、一个响应字节都没读到）。排除了 TLS 握手失败
   （ureq 的 `rtls.rs` 是 `complete_io` 即时握手，失败会报 `Connection failed: tls connection init failed`）。
3. 环境侧排除：DNS 正常（crm → 172.16.1.147），Python + 同一套 cert 直接 GET/POST 都 200；
   用项目自己的 `tls::build_client_config` 写 `examples/zoomkey_probe.rs` 单发请求也 200。
4. 用 `PROBE_FLOW=1` 让探针跑「GET getchallenge → POST login」**同一个 agent 两连请求** → 精确复现。
5. 根因：CRM 响应头是 `Connection: Upgrade, close`，而 ureq 的 `response::connection_option`
   只把**整串等于 `close`** 判为不可复用，于是把服务端已关闭的连接放回连接池；
   第二个请求复用到它 → 写进半关 socket → EOF。JIRA 服务端 keep-alive 正常，所以只有 CRM 挂。

### 修法

`src-tauri/src/zoomkey/mod.rs` 的 `build_runtime`：agent 加 `.max_idle_connections(0)` 关掉连接复用
（ureq `Pool::noop()` 在任一 max 为 0 时短路，`add` 直接 return）。内网低频，重建连接代价可忽略。
A/B 验证：关池两连请求都 200，开池第二发必现 `Unexpected EOF`。

### 排查工具

新增 `src-tauri/examples/zoomkey_probe.rs`（诊断用，不进默认构建）：
`cargo run --example zoomkey_probe -- <ca.pem> <cert.pem> <key.pem> <url> [POST_BODY]`，
环境变量 `PROBE_FLOW=1`（CRM 两连请求）、`PROBE_REPEAT=N`（同一请求发 N 次）、`PROBE_POOL=1`（启用连接池做对照）。

验证：`cargo test --lib` 135 passed；`cargo build` 通过（构建前已结束运行中的 sealbox.exe）。

### 补：根因的完整链条（前面那版写得不完整，以此为准）

1. CRM 响应头是 `Connection: Upgrade, close` **+ `Upgrade: h2`**（Apache mod_http2 的 h2 升级协商残留）。
2. ureq 的 `connection_option` 用 `eq_ignore_ascii_case("close")` **整串比较**，`"Upgrade, close"` 不等于
   `"close"`，于是判定为 KeepAlive → 不调 `set_unpoolable()` → 连接被放回池里。
3. 真实服务端在响应之后**还会补发一条 19 字节的 TLS application_data 记录**
   （`17 03 03 00 13 ...`，HTTP/2 GOAWAY），然后才断 TCP。
4. ureq 取用池中连接前只做一次非阻塞 `peek`（`Stream::serverclosed_stream`）：
   `Ok(0)`（FIN）和 `Ok(n>0)`（有残留字节）都判为「已关闭、丢弃」，**只有 `WouldBlock` 才判为可用**。
   而那条 GOAWAY 记录和 FIN 往往还没到 → peek 返回 `WouldBlock` → 判定可用 → 复用。
5. 第二个请求写进一条正在被服务端拆除的连接 → 读不到任何响应字节 →
   `read_next_line` 的 `Ok(0)` 分支 → `Network Error: Unexpected EOF`。

**最坑的一点：ureq 会自动重试幂等请求。**
`unit::connect_inner` 里 `Err(err) if err.connection_closed() && retryable && is_recycled` 会换新连接重试一次；
`Unit::is_retryable` 要求方法属于 DELETE/GET/HEAD/OPTIONS/PUT/TRACE **且 body 为空**。
所以：
- 用 **GET** 探测这个 bug → 被悄悄重试掉，看不出问题（我第一版探针和第一版单测都栽在这里）。
- **POST**（`login`，带 body）→ 不可重试 → 错误直接冒出来。

写回归测试必须用 POST，并且服务端要模拟「响应头声明 close 但先不断开 TCP」这个窗口
（`agent_does_not_reuse_a_connection_the_server_closed`）。A/B 已验证：去掉
`.max_idle_connections(0)` 该测试立刻失败。

排查手法补充：确认「服务端到底关没关 TCP」要看**底层 socket**，
`ss.recv()` 返回 `b''` 可能只是 TLS close_notify，不代表 TCP 已断。
用 `ss.detach()` 拿回 fd 再 `socket.socket(fileno=fd)` + `recv(1, MSG_PEEK)` 才准
（Windows 上 Python 的 `socket.peek` 不存在，要用 `recv(..., MSG_PEEK)`）。
